# plan2graph 기술 브리프 (외부 검토용 — ChatGPT 등)

> 목적: 외부 전문가에게 **사실 + 확정 설계 + 열린 질문**을 그대로 전달해 검토받기 위함.
> 작성 원칙: 의견 최소화, 검증된 사실과 확정 결정(ADR)만. 추천이 필요한 부분은 "열린 질문"으로 분리.
> 함께 보는 파일: `korean_dataset.md`(데이터 표현) + `sample_parsed.json`/`sample_corrected.json`(실제 그래프 샘플).

## 1. 목표 (불변)
한국형 **소버린 생성형 도면 엔진**. 입력(방 구성·인접·경계)으로 **완성도 있는 건축 평면도**(벽·방·문·창·치수)를 생성하고, **한국 건축법규를 준수**하며, **AutoCAD DXF + 이미지**로 출력. 단순 방 배치가 아니라 *그려서 쓸 수 있는 도면*이 목표.

## 2. 확정 설계 (ADR-0006, 2026-06-12 Accepted — 변경 금지, 변경 시 ADR supersede)
- **단일(ONE) 생성 엔진.** 모델 3개 직렬 체이닝·앙상블·남의 가중치 단순 파인튜닝은 기각.
- **SOTA의 *기법(부품)* 을 인용·조립**(모델 통째가 아님):
  - DiffPlanner: 벡터 직접 diffusion 골격 + 경계조건 (보유·검증, RPLAN FID 1.23 재현)
  - GSDiff: 정렬 손실 + 랜덤 자기지도(코너/벽 연결 정합) (코드 보유)
  - HouseDiffusion: 이산+연속 디노이즈(직각·평행·코너공유)
  - FMLM: 유효성 제약(constrained decoding, 벽 안닫힘/겹침 차단)
- **우리 novelty(=논문/제품 가치) = ① 법규-인식 생성 ② 완전 출력(문·창·기구·치수) ③ 한국 소버린 도메인.**
- **표현**: 코너(벽 교차점) + 벽(코너 엣지) + 방 폴리곤(벽 사이클) + 방 종류. 문·창·기구·치수는 *완성층*(neuro-symbolic, 생성 후)에서 채움.
- **학습**: 사전학습(글로벌 RPLAN, 선택 +CubiCasa) → 파인튜닝(한국 AI-Hub). "사전학습이 도움되나"는 가정 않고 콤보 매트릭스로 *측정*.
- **헤지**: DiffPlanner를 병렬로 굴려 *작동 파이프라인 + 비교 베이스라인 + 제품* 먼저 확보.
- 성공 기준: `FID ≈ DiffPlanner 동급(1.2~1.5)` AND `법규준수·완성도에서 SOTA 압도`. (FID만 이기는 건 목표 아님.)

## 3. 파이프라인 (현재 구현)
```
AI-Hub 원본(PNG + 부분 라벨)
  → R2G 파싱(비전검출 V2V + 조립 + 규칙) → 통일 그래프(geomgraph g-0.3)
  → [Parsed=파서출력]  /  [Corrected=파서출력+사람 정보보정(웹 에디터, edits/)]
  → 엔진(사전학습 글로벌 → 파인튜닝 한국)  ※ ADR-0006
  → 완성층(neuro-symbolic: 문·창·기구·축척)
  → cadrender → 이미지 + DXF
```
- 비교축(ADR-0008/0009): **Parsed ∥ Corrected** (같은 엔진, 입력 품질만 변수 = human-correction ablation). "T/G"·"자동" 용어는 폐기, Parsed/Corrected로 통일.
- 데이터 표현·스키마·통계·한국 위상·알려진 데이터 이슈는 → `korean_dataset.md`.

## 4. 자산 (실재)
- 데이터: 한국 AI-Hub(통일 그래프 40,495세대) + RPLAN(글로벌) + CubiCasa(기구).
- 엔진 코드: DiffPlanner(`~/diffplanner_work`, 검증)·GSDiff(보유). 한국형 13역할/18방 확장 패치.
- 법규: `rules_legal.py`(채광 §17①·환기 §17②·피난·최소면적, 국가법령 Open API), 생성 후 verify→repair 루프 연결.
- 렌더: `cadrender`(그래프→이미지+DXF, 검증).

## 5. 현재 상태 (사실)
- 엔진 데이터셋 변환됨: korean 23,706 / aihub_g_dual(Corrected) / RPLAN base.
- 학습된 체크포인트: `aihub_g_dual` 3단계(node·adjacency·partitioning) **8,000 step**(사전학습 node는 140k). → **얕게 학습됨.**
- 샘플 도면: 아직 생성 안 함(output 비어있음).
- → "강한 엔진이 잘 안 된다"의 현재 원인은 *설계*가 아니라 **학습 미성숙 + 아래 실패모드**로 보임.

## 6. 알려진 실패모드 (측정·확정된 사실)
1. **박스 회귀(폐기)**: 방=축정렬 bbox 표현 → 정답조차 99% 겹침. 폐기됨.
2. **방-표현 생성기 붕괴**: loss 수렴해도 도면 불가 — ① 순열 등변(위치인코딩 부재)으로 중복 방이 동일 박스로 완벽 겹침, ② MSE 모드평균 → 중앙붕괴. (현재 엔진의 핵심 난점.)
3. **연결공간 흡수**: R2G 파서가 복도·파우더룸(전실)을 옆 큰 방에 흡수 → 길쭉한 거실/드레스룸(전체의 **~24%**, 3001 중 720). 위상 허브 소실. (사람 보정 SPLIT으로 교정 가능 — 구현됨.)
4. **데이터 갭**: 축척(mm/px) 0%, 기구 0%, 문 스윙방향 57%만. (neuro-symbolic 추론으로 채우는 게 ADR-0006 방침.)

## 7. 열린 질문 (ChatGPT에게 — 중립적으로)
> 아래는 우리가 흔들려온 지점들. 확정 설계(§2)를 전제로, *근거 있는* 조언을 구함.

1. **완성도 있는 도면을 위한 출력 표현**: (a) 방 폴리곤 생성 + neuro-symbolic으로 벽·문·창 덧붙이기(현재), (b) 벽 그래프 직접 생성(GSDiff류, 공유벽 자동·겹침0), (c) 통합 마크업 단일 생성(FMLM류, 한 모델이 전부) — 우리 목표(완전+법규+한국)에 무엇이 최적이고 trade-off는? §6-2 붕괴문제 해결에 어느 게 유리?
2. **겹침/모드붕괴**를 *구조적으로* 막는 검증된 방법은? (순열불변 설계·인스턴스 토큰·diffusion·타일링 손실 등 중 무엇이 실증적으로 효과?)
3. **법규-인식 생성** 구현: diffusion guidance vs loss penalty vs 후처리 보정 — 비율(채광 1/10 등)·면적 제약을 생성 안에서 강제하는 현실적 방법?
4. **전이학습**: RPLAN 사전학습 → 한국 파인튜닝이 실제로 도움되나? 도메인 격차(중국형 RPLAN vs 한국 아파트)에서 음의 전이 위험과 완화책?
5. **데이터 갭(축척0%·기구0%)** 을 neuro-symbolic 추론으로 채우는 접근이 타당한가, 더 나은 길이 있나?
6. **novelty 충분성**: 법규준수+완전도면+한국 소버린이 *조립 엔진* 위에서 논문/제품으로 충분한 기여인가? 약하다면 어디를 보강?
7. **현재 8k-step 얕은 학습**으로 도면이 안 나오는 것 — 더 학습이 우선인가, 표현/아키텍처 변경이 우선인가? 판단 기준은?
