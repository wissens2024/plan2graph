## 🔴 [중대] 9자리 ID는 라벨종류 간 공유 키가 아니다 (2026-05-30 발견)

README §2.2는 "동일 도면의 여러 라벨을 {9자리} 키로 묶는다"고 했으나 **실제는 다르다.**

- 전체 인벤토리 결과: **FP 도면키 37,192개 중 SPA+STR을 함께 가진 키는 50개뿐**(우연한 숫자 일치). → 9자리 숫자는 라벨파일마다 고유하게 부여됨, 라벨종류 간 연결 의미 없음.
- **연결고리 = 이미지 내용**: 같은 도면의 PNG가 라벨종류 zip마다 **byte-identical**로 들어있다(검증셋 SPA↔STR SHA256 정확 매칭 63쌍 확인). 파일명/ID만 다름.
- **결론**: 한 도면의 SPA(방)+STR(문/벽)을 합치려면 **PNG 내용 해시(SHA256)로 그룹핑**해야 한다. 9자리 키 기준 묶기는 폐기.

### SPA∩STR 중복률 측정 완료 (2026-05-31, CRC32+크기 지문 방식)
**방법**: 원천 PNG를 SHA256으로 13GB 전부 푸는 대신, ZIP 중앙 디렉터리의 `CRC32+file_size`를 지문으로 사용(압축 해제 0). 검증셋에서 이 방식의 SPA+STR=63이 **기존 SHA256 결과 63쌍과 정확히 일치** → 방식 신뢰성 확인. (`unpack.py link`)

| split | PNG 엔트리 | 고유 도면(지문) | SPA+STR 동시 | 비율 |
|---|---|---|---|---|
| Validation | 4,159 | 3,778 | 63 | 1.7% |
| **Training** | **33,238** | **19,019** | **3,836** | **20.2%** |

- **그래프화 가능 표본 ≈ 3,899개**(Training 3,836 + Val 63). 4종 라벨 전부 보유(OBJ+OCR+SPA+STR) = Training 1,424개.
- 결정: 중복률 20.2%는 **해시(CRC) 그룹핑으로 SPA+STR 병합** 분기에 해당 → **계획대로 진행**. 이 3,836개가 방(타입라벨)+문+벽을 모두 가진 1급 데이터셋.
- STR만 보유(4,290) 도면은 방 타입라벨이 없음 → 후순위 STR중심 증강 후보(벽 폐곡선→방 영역 유도, 타입 미상). 1차 데이터셋에는 미포함.
- 산출물: `data/interim/linked_spa_str_training.json`(pairs: 지문→{SPA:key, STR:key, OBJ:, OCR:}), `linked_spa_str_validation.json`.

## scale 역산 (치수선 OCR) (2026-06-01)
- AI-Hub OCR 라벨엔 치수·면적·축척값 **0건**(방이름만). → 라벨로는 scale 불가.
- 원본 PNG에는 치수숫자·"축척=1/N"·"84㎡" 모두 선명 → **우리 OCR(rapidocr-onnxruntime, 경량·torch불요)로 역산**.
- **DPI 메타(144)는 신뢰 불가**: "축척=1/40"+DPI로 7.06인데 실측 13.6(2배). 리샘플링으로 stale. + 축척 텍스트 OCR 포착률 낮음. → **기하 방법만 신뢰**.
- **기하 방법(주력)**: 한 가로 치수열의 인접 숫자 i,i+1은 구간 중점에 놓임 → 중심거리 d_px=(v_i+v_{i+1})/2px → `scale=(v_i+v_{i+1})/(2·d_px)`. 숫자3+ 치수열만, 값 200~12000mm, 중앙값.
- **신뢰 게이트**: 침실 중앙값이 6~16㎡ + samples≥4면 'ok', 아니면 'low'/'none' → **격리**. (검증: 도면별 scale ~11~14mm/px, 침실 8~15㎡)
- 표본 12시트: ok 9 / low 2 / none 1 (~75%). 도면마다 축척 다름(1/40·1/80…) → scale은 **도면별** 필수.
- 적용: `scale_ocr.py pass`(전체 OCR→scale.csv) → `apply`('ok'만 그래프에 area_m2·meta.scale, 나머지 scale_quarantine.csv).
- ⚠️ 후속: 픽셀 임계(MIN_ETC_AREA_PX 등)는 축척의존 → scale 확보분은 ㎡ 기준으로 전환 검토.
