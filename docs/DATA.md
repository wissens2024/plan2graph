## 3. 처분 모델 (검수·회계의 단일 정의)

- **✅ 사용(use)**: 그래프화돼 데이터셋 편입(직접변환 또는 V2V/objocr 복구).
- **🛠 보정필요(fix)**: 살릴 수 있으나 아직 안 됨(위상 보정·V2V 대기·변환 실패·OBJ/OCR만). **변환·보정 성공 시 → 사용으로 이동**(보정필요↓·사용↑).
- **🚫 제외(excl)**: 영구 폐기 — 비-FP·중복 사본 둘뿐.
- **불변식**: 출처별 `사용+보정필요+제외 = 받은 원본`. 검수 콤보·종합 패널이 같은 소스 → 항상 일치.
- **검수 콤보 = 「라벨 구성 × 처분」 완전 회계** (한눈에 데이터 구성). 카테고리 고정 프레임, 숫자만 이동. → **ADR-0005**.

## 8. 알바 보정 최종 회계 — 검증·수정·추가·미검증 [2026-11-08 작업 종료]

재부여하므로 ID 매칭은 같은 방을 "삭제+추가"로 이중계상한다(짝 매칭률 ID 55.6% vs IoU **89.0%**).

> ⚠ **정정 [2026-11-09]**: "`corrected/edits/<id>.json`이 있다 = 사람이 그 도면을 열어
> 저장했다"는 전제는 **틀렸다.** 보정본 30,542건 중 **18,018건(59%)은 dedup 전파 복사본**

> **비율은 튼튼하고, 총량의 부호는 뒤집힌다.** 역할 확인률은 어느 축에서나 82~84%,
> 기하 동일률은 87~94%로 안정적이다 — 사본 가중이 비율을 왜곡하지는 않았다.
> 그러나 **방 수 순증은 전파본이 만든 허수다**: 전체 +1.3% · gated +9.3%인데,
> 사람 직접만 보면 **−5.0% · −2.0%** 로 **방이 줄어든다**(흡수 28,769 > 신설 18,134).
> 즉 사람이 직접 한 일은 "방을 쪼개 복도·파우더룸을 복원"이 아니라 **잘못 쪼개진 방을
> 합치는 쪽이 더 많았다.** 전파가 특정 다실(多室) 도면에 집중돼 신설이 부풀려졌다.
> → 방 수 증감을 근거로 쓰는 서술은 **반드시 '사람 직접' 축으로** 해야 한다.

> **서술 주의**: "보정은 효과가 없었다"는 틀린 요약이다. 사람이 12,524장을 직접 보고
> (사본까지 치면 30,542장을 덮어)
> 역할의 **82.1%를 맞다고 보증**, 17.9%를 고쳤고, 파서가 못 내는 축척을 채웠다.
> 기하 지표(drawable)가 +4.4pp만 오른 것은 보정이 기하를 거의 손대지 않았기 때문이며
> (기하 동일 88.3%), 이는 실패가 아니라 **파서 기하가 이미 맞았다는 확인**이다.

### 8.6 처분 — 보정 산출물 3종과 활용 범위 전환

1. **검증 자산** — 역할 82.1% · 기하 88.3%를 사람이 보증. 데이터셋 공개 시 `verified_by=human` 기록.

3. **규칙 채굴 소스** — 상위 12규칙이 역할 수정의 79.9%.

개발·평가 데이터가 된다(게이트 밖 21,509장 포함).

**알바 작업 종료.** 추가 사람 작업은 하지 않는다. 남은 보완은 기계로 — 규칙 적용(8.5) +
에디터에 없던 축(문 폭·스윙·벽 두께)은 실현 계층이 합성한다.

화면 기본 필터도 그렇게 맞춰 놨다"고 명시한다. 즉 **"못 한 것"이 아니라 "범위 밖"**이다.

### 처분 — 3갈래 + 출처 표기 (절대 섞지 않는다)

`verified_by = human | rule | none` 을 모든 레코드에 기록한다.

| 집단 | 건수 | 처분 | 이유 |
|---|--:|---|---|
| ① gated 미보정 | 1,452 | **규칙 12개 적용 → `rule`** | APT·게이트 통과 = 보정 집단과 동질. 학습 코퍼스 구멍을 사람 비용 0으로 메움 |
| ② APT 미보정(게이트 밖) | ~7,220 | 규칙 적용 → `rule` | 동질. 도면화 계층 **개발** 데이터 |
| ③ ROW + DEH | **2,195** | **규칙 적용 금지 · 보류** | 규칙은 APT 보정에서 채굴됐다. 연립·단독의 역할 체계가 같다는 근거가 없다 |

### ③은 순환논리를 끊는 평가셋이다

규칙은 알바 보정에서 채굴했다. 그 규칙으로 보정한 데이터로 평가하면 순환논리다.
미보정 집단(특히 ③)은 **규칙을 만든 사람들이 손대지 않은 유일한 데이터**다.

| 용도 | 데이터 | `verified_by` |
|---|---|---|
| 평가 정답지 | 사람 검증 12,524 직접(+전파 18,018 = 30,542) | `human` |
| 개발·학습 보강 | ①② 규칙 보정 ~8,672 | `rule` |
| **일반화 테스트(오염 0)** | **③ ROW+DEH 2,195** | `none` |

→ "APT로 만든 도면화 계층이 연립·단독에도 되는가"를 정직하게 검증한다. 도면 종류 문제
(아파트/연립/다세대)에 대한 답은 범위를 좁히거나 넓히는 것이 아니라
**APT로 개발 · ROW/DEH로 검증**이다.

### 8.8 중복 도면 통일 — 아직 안 끝났고, 다수결로는 끝낼 수 없다 [2026-11-09]

정본 현황판 = [DEDUP_STATUS.md §0](DEDUP_STATUS.md) · 작업표 = [DEDUP_WORKLIST.md](DEDUP_WORKLIST.md)
(`scripts/dedup_worklist.py`, 읽기 전용).

같은 도면이 데이터셋에 반복 등록돼 있다(41,409장 → 고유 17,847). 사본을 **서로 다르게**
보정한 그룹이 **1,124개** 남아 있다. 사람 보정은 2026-10-08에 끝났고 그 뒤 변경된 edits는
0건이므로 이 숫자가 최종이다.

**'다수안'은 쓸 수 없다.** 전파 때문이다(§8.1 정정). 상위 그룹 실측: "다수안 40건" =
사람 직접 1건 + 전파 39건. 전파본을 빼고 **독립 사람 판단**만 세면 APT·1세대 불일치
883그룹 중 **803(91%)이 동점** — 사실상 전부 **작업자 1명 대 1명**이다.
(독립다수 40 · 전파가 변종을 만든 단일판단 40)

| 분류 | 그룹 | 사본 | 학습 도면 | 처리 |
|---|--:|--:|--:|---|
| **A 구조 차이**(방 수가 다름) | **123** | 1,058 | **998** | 합치기/나누기 판단이 갈렸다 — 규칙으로 못 고친다 |
| **B 라벨 차이**(방 수 같음) | **36** | 243 | **229** | 역할 정규화 규칙으로 기계 통일 |
| **C 위치만 차이** | **12** | 95 | **95** | 조합까지 같고 어느 칸에 붙었나만 다름 |
| D 보류 | 712 | 3,175 | 0 | 학습 코퍼스에 한 장도 없음 — 통일해도 모델 영향 0 |

→ **남은 인간 작업 = A + C = 135그룹**(학습 도면 1,093장 = gated 보정 9,033장의 12%).

**갈린 지점은 소수다.** 방 수 차이는 ±1~2가 대부분이고, 차이가 난 역할은
`펜트리 103 · 기타 80 · 파우더룸 63 · 발코니 54 · 침실 46`에 몰려 있다(상위 5개 = 55%).
그래서 **그룹을 하나하나 판정하는 대신 정책 5개를 정하면** 대부분이 기계로 닫힌다:
펜트리 분할 기준 · 기타/알파룸/다목적공간 명명 · 파우더룸 분리 여부 · 발코니/테라스/실외기실
구분 · 전실 구분. ⚠ 적용 전 `펜트리`/`팬트리` alias 수정 필수(이 그룹들 안에도 `팬트리` 9건).
