# Plan2Graph 마스터 플랜 — 데이터셋 구축 ~ 온톨로지 기반 공간배치 생성 AI

> 최종 목표: 자연어 요구 → [제약그래프] → **생성 AI**가 배치그래프(도면) 생성 → **규제 AI**가 법규·위상 감독·교정 → 무결 도면 렌더.
> 글로벌(RPLAN·CubiCasa) **사전학습** + 한국형(AI-Hub) **파인튜닝**으로 학습.
> 개발=노트북, **학습·생성·대량추론=115 서버(2×RTX3080)**, 결과 뷰=서버 호스팅 콘솔.

## 현재 방향 (2026-06-09) — T-라인 / G-라인 분리 ([ADR-0002](adr/0002-tline-gline-separation.md))
도면 생성에 **두 패러다임**이 병존한다. **폴더·GUI에서 완전히 분리**하고 **도면 품질로만 합쳐 비교**한다.
- **T-라인**: 자동 detection→그래프(`v0~`, 위상 풍부/기하 빈약) → 위상모델(조합 자유) → **생성형 기하 AI**(`geom_gen`/geom_g0)로 좌표. ⚠️ 옛 규칙기반 treemap(`floorgeom.layout_rooms`)은 **폐기 예정 임시** — T 버튼 AI 이전 후 제거. [[treemap-deprecated-generative-is-goal]]
- **G-라인**: 원본→**SVG 변환**(원본→SVG)→**빌드**(SVG→그래프)(`g0~`, 위상+기하). 자동 베이스라인 후 알바가 SVG 보정·재빌드(보정필요→사용가능) → 위상모델(조합 적게) → **생성형 기하 AI**(`train_geom`/`geom_gen` · 개선=데이터·학습). ※ "빌드"=그래프 생성(T·G 공통), 원본→SVG는 'SVG 변환'(별개).
- 저장: `data/releases/{tline,gline}/`, `runs/{tline,gline}/`.
- 순서: **① 폴더·GUI 구조화 → ② G-라인 스키마 정교화(자동)**. 사람 검수는 이후.

## 0. 현재 위치 (2026-06-05)
- **P1 건축지식 구조화**: 온톨로지(OWL)·Topology 추론·법규엔진(SWRL+HermiT, 국가법령 API) ✓ / 면적법규·V2V STR 잔여

- **P3 생성**: 통계 baseline + **신경망(Set-Transformer, Relation-Aware)** + **자기교정 루프**(verify→repair) + 평가 하네스(+dwelling 매크로) ✓. **균형 매트릭스 완료 — 반전(신경망>규칙기반)**. 잔여: Constrained RL·Space Syntax·LLM Text-to-Graph·기하 생성.
- 한계: **N세대 floor-plate 데이터갭**(복도 미라벨) / 기하 도면 미구축 / 면적법규 전문가확정 대기 / 20장 정확도 게이트.

## 1. 개발·실행 환경 아키텍처 (laptop ↔ 115 server)

```
┌── 노트북 (개발) ──────────────┐         ┌── 115 서버 (2×RTX3080) ────────────┐
│ • 코드 작성·경량 샘플 검증      │  git    │ • 전체 데이터(AI-Hub 38GB+글로벌)   │
│ • config·스크립트·콘솔 UI       │ push →  │ • V2V/생성모델 학습·대량추론(GPU)   │
│ • git commit                   │ ← pull  │ • 데이터셋 빌드(전체)·평가          │
└────────────────────────────┘         │ • Streamlit 콘솔/대시보드 호스팅    │
        브라우저로 결과 조회  ◄── SSH터널/IP ─ │   (http://서버:8501)              │
                                          └──────────────────────────────────┘
```

**코드 동기화**: git (노트북=dev, 서버=pull 후 실행). 무거운 산출물(모델·데이터)은 git 제외(.gitignore), 서버 로컬 보관.
**데이터 적재**: AI-Hub zip·글로벌셋을 서버에 1회 전송. `config.py`는 환경변수 `PLAN2GRAPH_DATA`로 경로 추상화(노트북/서버 공용).
**실행**: 서버에서 `python -m plan2graph.<job>` CLI. 긴 작업은 nohup/tmux.
**결과 뷰**: 콘솔을 서버에서 `streamlit run admin.py --server.address 0.0.0.0` → 브라우저 접속. 데이터·모델·지표가 전부 서버에 있으므로 **"서버 결과를 그대로" 봄.**
**실험관리**: 버전 디렉터리(releases/) + 모델 체크포인트(models/) + 평가 JSON. 필요시 추후 W&B/MLflow.

### 환경 준비(서버)
- conda/venv + `requirements-server.txt`: 기존 + `torch`(CUDA) + `ultralytics`(YOLOv8-seg) 또는 `detectron2` + `torch-geometric`(PyG)
- CUDA 드라이버 확인, 2-GPU 데이터병렬

## 4. Phase 3 — 온톨로지 기반 공간배치 생성 AI (서버, GPU) [2026-06-05 상세화]

### 4-0. 스코프 — 3 트랙 (데이터로 확정, [[balanced-benchmark-neural-beats-baseline]])
| 트랙 | 상태 | 근거 |
|---|---|---|
| **단일세대 위상**(program→방-문-방 그래프) | ✅ 작동(생성+자기교정+평가) | 데이터 충분(세대별 도면) |
| **단일세대 기하**(위상→좌표·벽·렌더) | 🔜 다음 | 스파이크 입증(규칙기반 인접 95%·면적오차5%). 직사각형화·학습형 |
| **N세대 floor-plate**(다세대 한 층) | ⏳ 향후 | **데이터갭**: 복도 미라벨·유닛 미연결(감사 0% 통합). 복도추론/신규데이터 선결 |

> 최종 목표 "도면"은 기하(좌표/벽). 위상은 그 입력. N세대는 데이터 한계로 보류.

### 4-1. 생성 = Neuro-Symbolic, ablation으로 누적 (각 단계 delta = 논문 기여)
누적 순서, 각 단계 **균형 dwelling 매크로**로 측정(차이가 곧 기여):
1. 규칙기반(통계) — baseline ✅
2. **+ 신경망 Relation-Aware GNN(Set-Transformer)** ✅ — Neuro 기여(반전: 매크로 0.205→0.188)
3. + 위계(public/private/service) 명시 입력·제약 — 강화
4. **+ Symbolic Self-Correction 루프**(SWRL/온톨로지 검증→국소수정→근거 출력) ✅(loop) — Symbolic 기여(법규 off→on, v2 42→100%)
5. + **Constrained RL**(SWRL 위반 페널티 + Space Syntax 보상) — 신규(지표부터)
- **Text-to-Graph(§4 입구)**: 규칙기반(`text2graph`, 작동) → **LLM 파인튜닝**(hard/soft 분리). LLM은 후순위.
- **선택적 house_type 조건**(LLM이 타입 줄 수도/안 줄 수도 → 조건 dropout). 섞기+조건, 간섭 시 타입헤드.

### 4-2. 사전학습 축 — 버전 사다리 (전이학습 효과)
| 버전 | 사전학습 | 상태 | 검증 질문 |
|---|---|---|---|
| (v0) | none | ✅ | baseline |
| **v2** | CubiCasa(3,028) | ✅ 완료 | 중립(작아서) |
| **v3** | RPLAN(80,371, 27배) | 🔜 대기 | 대규모 글로벌이 **unseen·빈곤타입(DEH/ROW) 구제**하나? |
| **v4** | RPLAN+CubiCasa 결합 | 🔜 | 사전학습 축 완성(kitchen sink) |

> 코퍼스 축(v0 dual / v2 dual+V2V)과 **별개 축**. provenance 필터로 구분([[dataset-version-scheme]]).

### 4-3. GUI 구조 = ablation/figure 생성기 (단일 소스 = runs ledger `experiments.agg_summary`)
- **패널1 Ablation 사다리**: 구성요소(규칙기반→+신경망→+자기교정→+RL)별 균형 매크로 + delta. 버전 토글. = **논문 표**.
- **패널2 파이프라인 토글**: text→T2G→GNN→Symbolic검증·교정→위상도면. 단계 on/off로 같은 입력서 효과 대비(자기교정 끄면 문없는방 발생). = **architecture figure**.
- **패널3 단일샘플 근거**: reasoner가 잡은 위반(문없는방·고립·동선)+수정+규칙근거. = **qualitative figure**.
- 원칙: 하드코딩 0, 데이터셋·실험 바뀌면 자동 갱신(§1·§3 라이브화와 동일).

### 4-4. 평가
- **균형 소버린**: dwelling 매크로(APT/DEH/ROW 동등) + unseen + 법규(off→on) + 무결성·다양성·신규성 + program 충실도 + **Space Syntax(신규)**.
- A/B 축: 코퍼스(v0/v2) × 사전학습(none/CubiCasa/RPLAN/결합) × 생성기(규칙/신경망) × 루프(off/on).

# Plan2Graph 로드맵 — 사업계획서 1·2단계 정렬

> 전체 목표(사업계획서): 1단계 건축지식 구조화 도구 → 2단계 멀티모달 데이터셋 구축 → 3단계 온톨로지 기반 공간배치 생성 AI.
> **우리 현재 스코프 = 1단계 + 2단계(데이터셋 구축까지).** 3단계(생성모델)는 이 데이터셋 위에서 별도로 진행.

---

## 사업계획서 항목 ↔ 실제 구현 현황 (정직한 대조)

### 1단계 (5~6월): 건축 지식의 구조화 및 자동화 도구
| 사업계획서 항목 | 상태 | 비고 |
|---|---|---|
| 공간 온톨로지 (OWL) | ✅ 구현(경량) | `ontology.py` 18클래스·위계·관계. **추론기/SWRL 미연동** → 법규엔진과 함께 강화 필요 |
| **법규의 기계어 변환 (SWRL + 국가법령정보센터 API)** | ❌ **미구현** | `rules.py`는 위상 무결성만. 강행규정(피난거리·채광·침실최소면적)→SWRL 규칙셋, 모듈형 법규 DB 미착수 |
| **Vision-to-Vector (YOLO-seg)** | ✅ **구현**(`v2v_infer`·`yolo_train`, ultralytics) | SPA(방) mAP~0.90, STR(문/창) 약함. 라벨 없는 도면·글로벌셋의 검출 엔진. ※문서의 "Mask R-CNN"=옛 명칭, 실제는 YOLO-seg. R-CNN 앙상블은 STR 보강 옵션(미구현) |
| Topology Extraction | ✅ 구현·고도화 | `topology.py` 문+발코니+개방통로. 핵심 완성 |

### 2단계 (7~9월): 한국형 멀티모달 데이터셋 구축
| 사업계획서 항목 | 상태 | 비고 |
|---|---|---|
| 한국형 파인튜닝셋 (AI-Hub 48,033) | ✅ 거의 완료 | **6,210 세대 그래프** + split/card. 교정·품질향상 진행 중 |
| **글로벌 사전학습셋 (RPLAN, CubiCasa5k)** | ✅ **변환 완료** | RPLAN 80,371/80,788 정상(99.5%) + CubiCasa 3,018/5,000(60.4%) = pretrain 정상 ≈83,389. 공통 스키마 0.2·role=pretrain 전량 발행(2026-06-04, NOTES 기록) |
| **공통 포맷 통일 (글로벌 ↔ AI-Hub 동일 스키마)** | ⚠️ 변환됨·교차검증 잔여 | 두 글로벌셋이 `common.to_record`로 동일 스키마 발행됨. AI-Hub와 노드/엣지/클래스 매핑 동일성 **정량 교차검증**은 후속 |

### 결론
- **제대로 됨**: OWL스키마(경량)·Topology·AI-Hub 데이터셋(한국형)·법규 엔진(v1/v2)·**글로벌 사전학습셋 변환(RPLAN+CubiCasa ≈83k 정상)**.
- **사업계획서상 미구현(스코프 내)**: ① 공통포맷 정량 교차검증(글로벌↔AI-Hub) + 결합 릴리스(recipe) ② Vision-to-Vector(STR 본학습) ③ 법규 SWRL 큐레이션 확장.
- ⚠️ 정정: 앞서 "V2V는 정당한 생략"이라 했으나, 그건 *AI-Hub 처리 한정*. **사업계획서는 V2V를 1단계 도구로 명시** → 라벨 없는 도면·글로벌셋엔 필요. 생략이 아니라 **보류**로 재분류.

## 잔여 작업 트랙 (사업계획서 정렬)

### 트랙 1법규. 법규 기계어 변환 엔진 (1단계 핵심 누락)
- 국가법령정보센터 공개 API로 강행규정 수집 → **SWRL 핵심 규칙셋**(피난거리·채광·침실최소면적) → 예외조항 확장 모듈형 법규 DB.
- 선행: **scale 확보**(㎡ 변환) — 면적·거리 규칙의 전제. CSV 확보 또는 치수선 OCR 역산.
- 온톨로지 추론기(owlready2 reasoner/Pellet) 연동 → 그래프를 법규로 검증.

### 트랙 2V2V. Vision-to-Vector (1단계 도구)
- YOLO-seg 인스턴스 세그멘테이션: 도면 이미지 → 벽체·개구부·방 영역. (※"Mask R-CNN"=옛 명칭, 실제 구현은 YOLO-seg)
- 용도: 라벨 없는 도면 처리, 글로벌셋(raster) 정규화. **AI-Hub 라벨로 학습데이터 부트스트랩 가능**(이미 폴리곤 보유 → 학습셋 무료 확보).
- 판단 필요: 3개 표적셋(AI-Hub 라벨·RPLAN 시맨틱·CubiCasa SVG)은 일부 주석 보유 → V2V가 *필수*인지, *제안 산출물*인지 사용자 확인.

### 트랙 3글로벌. 글로벌 사전학습셋 + 공통포맷
- 공통 그래프 스키마 명세 **확정**(현 schema.py를 표준으로) → RPLAN·CubiCasa5k 어댑터(`adapters/`) → 동일 layout+constraints 포맷으로 변환.
- 검증: AI-Hub와 글로벌셋이 **같은 노드/엣지 규약**을 따르는지(클래스 매핑·정규화 좌표·via 종류) 교차 확인.

### 트랙 P. 프로그램 완성도 (양 단계 공통 인프라 — 진행 중)
- 교정 워크플로(일괄교정·수동편집·결정정책화), 신규도면 증분 인제스천, 20장 정확도 게이트, export(PyG/JSONL). (앞서 논의한 A~E)

## 제안 우선순위
0. ✅ **scale 확보** — 치수선 OCR 역산(도면별, 신뢰게이트). v0 64.6% 확보.
1. ✅ **글로벌 어댑터(트랙3글로벌)** — RPLAN 80,788 + CubiCasa 5,000 공통 스키마 변환 완료(2026-06-04).
2. **공통포맷 교차검증 + 결합 릴리스** — 글로벌↔AI-Hub 노드/엣지/클래스 매핑 동일성 정량 확인 → `recipe.json`으로 v2(aihub+cubicasa)·v3(+rplan) freeze. ← **다음**
3. **AI-Hub 데이터셋 마감** — 교정 일괄화(트랙P) + 20장 정확도 게이트(현 precision 90.3%).
4. **법규 SWRL 엔진(트랙1법규)** — catalog.json design 80 큐레이션→구현 확장.
5. **V2V(트랙2V2V)** — STR 본학습(현 mask mAP 0.47→), single 11,209 복구.

> 3단계(생성 AI)는 위 데이터셋·온톨로지·법규엔진을 입력으로 별도 진행.
