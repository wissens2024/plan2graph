# Plan2Graph 마스터 플랜 — 데이터셋 구축 ~ 온톨로지 기반 공간배치 생성 AI

## 1. 개발·실행 환경 아키텍처 (laptop ↔ 115 server)

```
┌── 노트북 (개발) ──────────────┐         ┌── 115 서버 (2×RTX3080) ────────────┐
│ • 코드 작성·경량 샘플 검증      │  git    │ • 전체 데이터(AI-Hub 38GB+글로벌)   │
│ • config·스크립트·콘솔 UI       │ push →  │ • V2V/생성모델 학습·대량추론(GPU)   │
│ • git commit                   │ ← pull  │ • 데이터셋 빌드(전체)·평가          │
└────────────────────────────┘         │ • Streamlit 콘솔/대시보드 호스팅    │
        브라우저로 결과 조회  ◄── SSH터널/IP ─ │   (http://서버:8501)              │
                                          └──────────────────────────────────┘
```

**코드 동기화**: git (노트북=dev, 서버=pull 후 실행). 무거운 산출물(모델·데이터)은 git 제외(.gitignore), 서버 로컬 보관.
**데이터 적재**: AI-Hub zip·글로벌셋을 서버에 1회 전송. `config.py`는 환경변수 `PLAN2GRAPH_DATA`로 경로 추상화(노트북/서버 공용).
**실행**: 서버에서 `python -m plan2graph.<job>` CLI. 긴 작업은 nohup/tmux.
**결과 뷰**: 콘솔을 서버에서 `streamlit run admin.py --server.address 0.0.0.0` → 브라우저 접속. 데이터·모델·지표가 전부 서버에 있으므로 **"서버 결과를 그대로" 봄.**
**실험관리**: 버전 디렉터리(releases/) + 모델 체크포인트(models/) + 평가 JSON. 필요시 추후 W&B/MLflow.

### 환경 준비(서버)
- conda/venv + `requirements-server.txt`: 기존 + `torch`(CUDA) + `ultralytics`(YOLOv8-seg) 또는 `detectron2` + `torch-geometric`(PyG)
- CUDA 드라이버 확인, 2-GPU 데이터병렬

## 4. Phase 3 — 온톨로지 기반 공간배치 생성 AI (서버, GPU)

### 4-1. Text-to-Graph (자연어 → 제약그래프)
- ① Domain-Adaptive: "4인가족 84㎡" → {거실1,침실3,화장실2,LDK} 노드·엣지 매핑
- ② Constraint Extraction: hard(법규·필수) vs soft(선호) 분리 → 목적함수 입력
- 1차: 규칙·템플릿 기반 → 이후 LLM 파인튜닝

### 4-2. 생성 모델 (배치그래프 생성)
- **baseline(통계, 완료)** → **신경망**: Relation-aware GNN / graph-diffusion(GSDiff류)
- **글로벌 사전학습 → 한국형 파인튜닝** (전이학습)
- 출력: 위상그래프 → (확장) 기하 좌표 배치 → 도면 렌더

### 4-3. Neuro-Symbolic (규제 AI 감독)
- **방식 A 사후검증**: 생성 → `rules_swrl.check_legal_swrl` → 위반시 재생성/국소수정 (Self-Correction 루프)
- **방식 B Constrained RL**: SWRL 위반=강페널티 보상 + Space Syntax 지표 → 규제 준수 학습
- 동일 법규엔진(rules_swrl)을 두 시점에서 호출

### 4-4. 평가
- 공용 하네스(고정 test): 위상무결성·**법규통과율**·인접사실성·다양성·신규성 + (신경망) FID류·program충실도
- **A/B**: v0 vs v1 vs v2 데이터 / baseline vs 신경망 / 규제루프 on·off

# Plan2Graph 로드맵 — 사업계획서 1·2단계 정렬

> 전체 목표(사업계획서): 1단계 건축지식 구조화 도구 → 2단계 멀티모달 데이터셋 구축 → 3단계 온톨로지 기반 공간배치 생성 AI.
> **우리 현재 스코프 = 1단계 + 2단계(데이터셋 구축까지).** 3단계(생성모델)는 이 데이터셋 위에서 별도로 진행.

---

## 사업계획서 항목 ↔ 실제 구현 현황 (정직한 대조)

### 1단계 (5~6월): 건축 지식의 구조화 및 자동화 도구
| 사업계획서 항목 | 상태 | 비고 |
|---|---|---|
| 공간 온톨로지 (OWL) | ✅ 구현(경량) | `ontology.py` 18클래스·위계·관계. **추론기/SWRL 미연동** → 법규엔진과 함께 강화 필요 |
| **법규의 기계어 변환 (SWRL + 국가법령정보센터 API)** | ❌ **미구현** | `rules.py`는 위상 무결성만. 강행규정(피난거리·채광·침실최소면적)→SWRL 규칙셋, 모듈형 법규 DB 미착수 |
| **Vision-to-Vector (Mask R-CNN)** | ⚠️ **미구현(재검토 필요)** | AI-Hub는 라벨 보유라 우리가 안 씀. 그러나 사업계획서의 **1단계 도구 산출물**이고 **라벨 없는 도면·글로벌셋 처리에 필요** |
| Topology Extraction | ✅ 구현·고도화 | `topology.py` 문+발코니+개방통로. 핵심 완성 |

### 2단계 (7~9월): 한국형 멀티모달 데이터셋 구축
| 사업계획서 항목 | 상태 | 비고 |
|---|---|---|
| 한국형 파인튜닝셋 (AI-Hub 48,033) | ✅ 거의 완료 | **6,210 세대 그래프** + split/card. 교정·품질향상 진행 중 |
| **글로벌 사전학습셋 (RPLAN, CubiCasa5k)** | ✅ **변환 완료** | RPLAN 80,371/80,788 정상(99.5%) + CubiCasa 3,018/5,000(60.4%) = pretrain 정상 ≈83,389. 공통 스키마 0.2·role=pretrain 전량 발행(2026-06-04, NOTES 기록) |
| **공통 포맷 통일 (글로벌 ↔ AI-Hub 동일 스키마)** | ⚠️ 변환됨·교차검증 잔여 | 두 글로벌셋이 `common.to_record`로 동일 스키마 발행됨. AI-Hub와 노드/엣지/클래스 매핑 동일성 **정량 교차검증**은 후속 |

### 결론
- **제대로 됨**: OWL스키마(경량)·Topology·AI-Hub 데이터셋(한국형)·법규 엔진(v1/v2)·**글로벌 사전학습셋 변환(RPLAN+CubiCasa ≈83k 정상)**.
- **사업계획서상 미구현(스코프 내)**: ① 공통포맷 정량 교차검증(글로벌↔AI-Hub) + 결합 릴리스(recipe) ② Vision-to-Vector(STR 본학습) ③ 법규 SWRL 큐레이션 확장.
- ⚠️ 정정: 앞서 "V2V는 정당한 생략"이라 했으나, 그건 *AI-Hub 처리 한정*. **사업계획서는 V2V를 1단계 도구로 명시** → 라벨 없는 도면·글로벌셋엔 필요. 생략이 아니라 **보류**로 재분류.

## 잔여 작업 트랙 (사업계획서 정렬)

### 트랙 1법규. 법규 기계어 변환 엔진 (1단계 핵심 누락)
- 국가법령정보센터 공개 API로 강행규정 수집 → **SWRL 핵심 규칙셋**(피난거리·채광·침실최소면적) → 예외조항 확장 모듈형 법규 DB.
- 선행: **scale 확보**(㎡ 변환) — 면적·거리 규칙의 전제. CSV 확보 또는 치수선 OCR 역산.
- 온톨로지 추론기(owlready2 reasoner/Pellet) 연동 → 그래프를 법규로 검증.

### 트랙 2V2V. Vision-to-Vector (1단계 도구)
- Mask R-CNN 인스턴스 세그멘테이션: 도면 이미지 → 벽체·개구부·방 영역.
- 용도: 라벨 없는 도면 처리, 글로벌셋(raster) 정규화. **AI-Hub 라벨로 학습데이터 부트스트랩 가능**(이미 폴리곤 보유 → 학습셋 무료 확보).
- 판단 필요: 3개 표적셋(AI-Hub 라벨·RPLAN 시맨틱·CubiCasa SVG)은 일부 주석 보유 → V2V가 *필수*인지, *제안 산출물*인지 사용자 확인.

### 트랙 3글로벌. 글로벌 사전학습셋 + 공통포맷
- 공통 그래프 스키마 명세 **확정**(현 schema.py를 표준으로) → RPLAN·CubiCasa5k 어댑터(`adapters/`) → 동일 layout+constraints 포맷으로 변환.
- 검증: AI-Hub와 글로벌셋이 **같은 노드/엣지 규약**을 따르는지(클래스 매핑·정규화 좌표·via 종류) 교차 확인.

### 트랙 P. 프로그램 완성도 (양 단계 공통 인프라 — 진행 중)
- 교정 워크플로(일괄교정·수동편집·결정정책화), 신규도면 증분 인제스천, 20장 정확도 게이트, export(PyG/JSONL). (앞서 논의한 A~E)

## 제안 우선순위
0. ✅ **scale 확보** — 치수선 OCR 역산(도면별, 신뢰게이트). v0 64.6% 확보.
