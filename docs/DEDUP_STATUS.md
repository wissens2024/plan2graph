## 4. 불일치가 왜 생기나 (표본 관찰)

알바마다 판단이 갈리는 지점이 반복된다:

- **파우더룸 유/무** — 같은 칸을 욕실 일부로 볼지 파우더룸으로 뗄지
- **알파룸 vs 기타 vs 다목적공간** — 애매한 여유 공간의 이름
- **펜트리 개수** — 주방 수납을 1개로 볼지 2개로 쪼갤지
- **대피공간 / 실외기실** 인식 여부

> ※ 최악 사례: 한 도면(사본 320장)을 **146번**, 그것도 **90가지로 다르게** 보정함.
> 이 그룹은 **현관이 4개** = 세대분리 실패(한 장에 여러 세대)라 보정 자체가 무의미할 수 있다.
> 상위 불일치 그룹 상당수가 여기 해당 → **세대분리부터 고치는 게 먼저**일 수 있음.

| 서명 신뢰도 | 사본 2+ 그룹 5,253개 중 좌표 20개 미만(빈약) = **46개(0.9%)** → 화면에 `서명약함` 경고 표시 |

## 6. 도구 (이번에 만든 것)

| | 무엇 |
|---|---|
| `scripts/dedup_index.py` | 전체 스캔 → 그룹·변종·불일치 계산. **읽기 전용**. 산출: `data/staging/dedup_index.json`, `docs/DEDUP_CONFLICTS.md` |
| `src/plan2graph/dedup.py` | 서명·보정비교·좌표변환 핵심 |
| `src/plan2graph/dedup_review.py` | 🔁 중복 검수 화면 + API(`/dedup`) |
| 화면 기능 | 그룹 목록 → 변종 카드 나란히(원본 도면 위에 역할 색칠) → **다수안 대비 차이**(`+파우더룸` `−펜트리`) 표시 → 골라서 전파 |
| 전파 버튼 2종 | `미보정 N건 채우기`(안전, 기존 보정 안 건드림) · `그룹 전체 통일`(덮어씀 — **자동 백업** 후) |
| 백업 위치 | `data/staging/corrected/_dedup_backup/<시각>_<그룹>/` |
| 출처 기록 | 전파본 meta에 `correction_source=propagated`, `propagated_from`, `dedup_group` |
