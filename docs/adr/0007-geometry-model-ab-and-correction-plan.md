# ADR-0007: T·G = 기하모델 A/B 비교 + 보정 단계(자동→인간) + 돌림 방지

Status: Superseded by ADR-0008
Date: 2026-06-12
Deciders: wissens2024

## 한 줄 요약
T-라인 / G-라인을 **"같은 파이프라인, 기하모델만 다른 A/B 비교"** 로 재정의한다. T = 약한 기하(박스, baseline·증명), G = 강한 기하(diffusion, ADR-0006). 데이터는 통일하되 추출 경로가 출처별로 다르다(AI-Hub=원본→SVG→**알바 SVG보정**→build→그래프 / RPLAN·CubiCasa=직접 그래프). 통일 그래프는 **T·G 공용**. 보정은 **데이터 빌드 단계=인간(알바, SVG) / 출력 단계=자동(neuro-symbolic, T·G 공통)** 두 위치로 나눈다. **도면이 안 나오면 기하모델 부품만 의심하고 전체 재설계는 금지(돌림 방지).**

---

## Context

1. **돌림(loop)이 진짜 문제였다.** 도면이 안 나올 때마다 "전체 설계가 문제"라며 통째로 다시 했다(treemap→박스→GSDiff→DiffPlanner→…). 그러나 실패한 건 **항상 한 부품 = 기하모델**이었다. 한 부품 고장을 전체 재설계로 키운 것이 돌림의 원인.

2. **확정 사실:** 위상만으로는 도면을 못 그린다 — **T-라인이 이미 증명**. 위상(✅)이 있어도 기하가 약하면 도면(❌).

3. **T-라인의 기하모델은 *약한* 것이지 *없는* 것이 아니다**(박스/treemap). 그래서 "위상 + 약한 기하 = 못 그림"의 **baseline·증명**으로 가치가 있다 → 그대로 살린다.

4. **설계(추출 → 위상 + 기하 → 보정 → 렌더)는 옳다.** 분해 구조는 DiffPlanner(노드+인접→분할)와 동일하다. 차이는 기하 부품 하나(우리 박스회귀 vs diffusion).

5. **비교의 함정:** 현재 T(v0~)와 G(g0~)는 **데이터가 달라** 기하모델 효과를 깨끗이 비교할 수 없다.

6. **보정(correction)은 현재 자동화만** 있고 인간 튜닝 개입은 없다. 향후 G-라인에 알바(인간) 보정을 도입할 계획.

---

## Decision

### 1. T·G 재정의 = 기하모델 A/B 비교
같은 파이프라인을 공유하고 **기하모델만** 다르게 둔다:

```
[공유]  데이터 추출 → 통일 그래프 → 위상모델 → [기하모델] → 보정 → 렌더(이미지+DXF)
                                              ↑ 여기만 변수
  T-라인:  기하모델 = 약함(박스)        ← baseline. "위상 + 약한 기하 = 못 그림" 증명
  G-라인:  기하모델 = 강함(diffusion)   ← ADR-0006 소버린 엔진. 제대로 그림
```
→ 비교가 **기하모델 효과를 격리**한다. (ADR-0002의 "T/G 분리"를 "기하모델 A/B"로 정밀화.)

### 2. 데이터 추출·통일 (비교의 전제 · T·G 공용)
세 출처를 **모두 한 그래프 규격으로 통일**한다. 단 **추출 경로가 출처별로 다르다**:
- **AI-Hub(한국):** 원본 → **SVG 변환** → **[알바 SVG 보정]** → **build** → 그래프. (비전 추출 노이즈를 사람이 SVG에서 고침 — 알바 개입은 *여기*.)
- **RPLAN · CubiCasa:** 원본 → **SVG 없이 직접** → 그래프. (이미 정형/벡터 데이터라 SVG·사람보정 불필요.)
- → **추출된 통일 그래프는 T·G 공용.** 비교 시 같은 데이터 → 기하모델만 변수.
- 부수 과제: **한국 실제 방 수·구성 검증**(병합 다세대 분리·fragment 제거). "한국=12~18방"은 인식 오류 의심 → 실제 수치 확정 후 엔진 방 수용량 결정.

### 3. 보정(correction) — 두 위치
| 위치 | 누가 | 무엇 | 비고 |
|---|---|---|---|
| **데이터 빌드 단계** | **알바(인간)** | **SVG 보정: 위상 연결 + 문 방향 + 축척(길이 1개)** → build → 그래프 | AI-Hub 원본(SVG 경유)에만. **산출 그래프는 T·G 공용.** 최소 개입(관계 선언·문방향·축척길이), "derive-dont-duplicate" 원칙. 축척=컴퓨터 스냅+사람 길이입력(같은 단지 공유). |
| **출력(생성 후) 단계** | **자동**(neuro-symbolic 루프) | 기하 정합 + 법규(rules_legal) | T·G 동일. 인간 개입 없음. |
| **병행 연구** | 자동 | **자동 기하 보정 고도화**(보정엔진) | 인간 개입 최소화 목표 |

- **알바 보정의 위치 = "원본→SVG→보정→build→그래프"의 SVG 단계**(데이터 빌드), *출력 도면 보정이 아님*. (ADR-0003 G-라인 파이프라인과 일치.)
- RPLAN·CubiCasa는 SVG·알바 단계가 없다(직접 그래프).

### 4. 돌림 방지 (1급 결정)
> **도면이 안 나오면 = 기하모델(부품) 문제로 좁힌다.** 위상·데이터·보정·렌더·파이프라인은 건드리지 않는다. **전체 재설계 금지.** 부품(기하모델: 박스→diffusion 등)만 교체하고 **측정(FID + 법규준수 + 완성도)** 으로 판정한다.

## 전체 파이프라인
```
  [데이터 추출 → 통일 그래프 (T·G 공용)]
    AI-Hub 원본  → SVG → [알바 SVG보정: 위상연결·문방향] → build → 그래프
    RPLAN 원본   → (SVG 없이) 직접 ─────────────────────────────→ 그래프
    CubiCasa 원본 → (SVG 없이) 직접 ─────────────────────────────→ 그래프
                              │
                        위상모델(방 연결)
                              │
              ┌───────────────┴───────────────┐
        T: 약한 기하(박스)            G: 강한 기하(diffusion, ADR-0006)
              └───────────────┬───────────────┘
                  자동 보정(neuro-symbolic 루프) — T·G 동일
                              │
                        cadrender → 이미지 + DXF
                              │
                  비교(FID·법규준수·완성도): T ∥ G
```

## Roadmap
1. **데이터 통일** — 세 출처 그래프 규격 통일(동작 중) + **한국 방 수 검증**(fragment·병합 정리).
2. **G 기하모델 = diffusion 구현** — ADR-0006 엔진, **우리 통일 그래프 입력**(DiffPlanner 포맷으로 변환 ❌). 핵심 한 부품.
3. **T 기하모델 = 약한 박스 그대로** — baseline.
4. **같은 데이터로 T ∥ G 비교** — 기하모델만 변수.
5. **자동 보정 루프** — 두 라인 공통.
6. **G에 알바 보정**(위상연결·문방향) + **자동 기하 보정 연구** 병행.

---

## Considered Alternatives (기각)
- **T·G를 전혀 다른 파이프라인/데이터로 두기** — 기하모델 효과를 격리 못 해 비교 무의미. 기각(→ 데이터·파이프라인 공유, 기하모델만 변수).
- **T-라인 폐기** — 기각: "위상+약한기하=못그림"의 증명·baseline 가치가 있어 살림.
- **G 기하를 DiffPlanner 포맷으로 변환해 학습** — 기각: 우리 통일 그래프 철학과 반대 + DiffPlanner 8방 한도(한국 부적합, 2026-06-12 실측). G 엔진은 우리 통일 그래프로 학습.
- **인간 보정을 전 기하로 확대** — 기각: 최소 개입(위상연결·문방향)만, 나머지는 자동 보정 연구로.

---

## Consequences
- **Positive:** 기하모델만 변수인 **깨끗한 T∥G 비교** · 돌림 종식(부품 단위로 좁힘) · G=사람 손 들어간 고품질 라인 · 자동/인간 보정 단계화로 점진 품질↑.
- **Negative:** 데이터 통일·방수 검증 선행 필요. G diffusion 기하 구현은 ADR-0006의 고난도 작업.
- **헤지:** 옵션1(DiffPlanner) 병렬 베이스라인(ADR-0006) 유지.
