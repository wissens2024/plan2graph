```
[글로벌 사전학습셋]            [한국형 파인튜닝셋]         [평가: AI-Hub 동결 test]
 CubiCasa/RPLAN  ──사전학습──▶  AI-Hub(v0)  ──파인튜닝──▶  test 518장 (전 버전 공유)
   (선택)          50ep          100ep                       │
                                  │                          ├─ 규제루프 off/on
```

## 2. 직교 5축 (이 5개를 섞지 말 것 — 혼동의 뿌리였음)

| 축 | 값 | 의미 | 결정 위치 |
|---|---|---|---|
| **① 데이터버전** | v0·v1·v2·v3 | 학습 데이터 조합(AI-Hub/+보정/+CubiCasa/+RPLAN) | DATASET_DESIGN · recipe |
| **② 생성기** | 규칙기반(알고리즘) · 신경망(set-transformer) | 통계 baseline vs 학습모델. **신경망은 모델 1종** | `eval_gen` · `train_gen` |
| **③ 학습레짐** | 미배치 → 배치 | 학습 **절차 성숙**(모델 동일, "버전" 아님) | `train_gen.train(batch_size)` |
| **④ 추론/규제** | temperature · 규제루프 on/off | 다양성 조절 · 법규 자동보정 | `eval_gen` · `gen_loop` |
| **⑤ 평가렌즈** | 전체 · seen · unseen | 같은 test를 보는 각도 | `eval_gen.generalization_diag` |

> ⚠️ "v1/v2"는 ①(데이터)에서만 쓴다. ③(학습레짐)을 "set-transformer-v1/v2"로 부르던 건 **폐기**(이름 충돌).
> 신경망 라벨은 버전꼬리표 없이 `신경망(set-transformer)` 하나.

## 3. 모델 — set-transformer (`train_gen._build_model`, EdgeModel)

방을 **순서 무관 집합**으로 보고 어떤 방끼리 무엇으로 연결되는지 예측하는 **링크예측기**.

- 방 타입 → `Embedding(48)` → `TransformerEncoder`(d_model 48, 2층, 4헤드, ffn 96, dropout 0) → 방별 맥락 `h` + 전역 program 맥락 `g`(평균).
- 방 쌍 (i,j): `[h_i+h_j, |h_i−h_j|, g]` → 두 헤드: **edge**(연결 여부) + **via**(연결 종류: door/open/balcony/…).
- 입력 = program(방 타입 집합), 출력 = 인접 그래프. ("Set Transformer" 논문의 ISAB/PMA가 아니라 일반 TransformerEncoder의 집합 self-attention.)

## 4. 학습 절차 — 두 모듈 (조합학습 vs 전이학습, 분리)

- **현재 단계 = 데이터셋 조합학습** (`train_combine.train`): 여러 소스를 **합쳐 한 데이터셋으로 한 번에 100ep 학습**(전이학습 아님). 어떤 조합이 최고인지 비교. → [[combine-matrix-running]]
- **다음 단계 = 전이학습** (`train_gen.train`): `--pretrain global_*`(50ep) → `--finetune`(100ep). **별도 모듈·메뉴**(섞지 않음). noPretrain은 파인튜닝 100ep만(동일 예산 공정 비교).
- **공유**: 모델 구조(set-transformer)·featurize·평가지표(`_metrics`)는 동일 → 공정 비교. 학습 루프만 모듈별 보유.
- **배치학습**: 가변 방수를 패딩+어텐션마스크로 한 배치(64)에 쌓아 통과 + 특징 1회 사전계산(미배치 대비 수배 가속).
- **손실 = 전 방-쌍 BCE(연결여부) + 양성쌍 via CE.** *배치 레짐은 음성 서브샘플링 없이 전 쌍 사용*(옛 `neg_ratio`는 미배치 잔재). 최적화 Adam(lr 1e-3), 시드 고정(`exp.seed_everything`).
- **재현**: run_id = `gen-<버전>-neural-<arch>-<pretrain|noPretrain>-seed<N>`. **각 학습의 정확한 파라미터는 `runs/<run_id>/meta.json`의 `condition`에 전량 보존**(checkpoint.pt·train.log 함께). 체크포인트는 git 제외(시드+코드로 재생성), 메타·지표·원장만 git 추적.

### 4-A. 학습 사양 (Training spec — 논문 인용용)

| 항목 | 값 |
|---|---|
| 모델 | set-transformer 링크예측기 (일반 TransformerEncoder의 집합 self-attention) |
| 임베딩 | 48차원 |
| 인코더 | 2층 · 4헤드 · FFN 96 · dropout 0 |
| 출력 헤드 | edge(연결여부, BCE) + via(연결종류: door/open/balcony, CE) |
| 입력 → 출력 | program(방 타입 집합) → 방-쌍 인접 그래프(위상) |
| 손실 | 전 방-쌍 BCE + 양성쌍 via CE (음성 서브샘플 없음) |
| 최적화 | Adam, lr 1e-3 |
| 배치 | 64 (패딩+어텐션마스크, 크기 버킷팅) |
| 에폭 | 100 (조합 단일학습 / 전이학습 파인튜닝); 전이학습 사전학습 50 |
| 시드 | 42 · 1 · 2 · 3 · 4 (5시드 → 평균±표준편차) |
| 생성 온도 T | eval=모델 기본 · 일반화/dwelling 진단=0.85 (*논문 보고 시 통일 권장*) |
| 평가셋 | AI-Hub 균형 동결 test(APT·DEH·ROW 동등, 전 버전 공유) |
| 평가 항목 | eval(전체) · seen/unseen(일반화) · dwelling(주거형태) · 규제루프 off/on |
| 재현 소스 | `runs/<run_id>/meta.json`(condition 전체) · checkpoint.pt · train.log · `runs/index.jsonl`(원장) |

> 논문 작성 시: 표의 값은 코드 기본값이며, **버전·시드별 실제 사용값은 `runs/<run_id>/meta.json`이 정본**(여기서 발췌). 온도 T는 현재 eval/진단이 달라 보고 전 통일 필요.

## 5. 평가 (`eval_gen`)

- **벤치마크 앵커 = AI-Hub 동결 test 518장**(`_frozen_test.json`, v0에서 정의·전 버전 공유). 이것만 불변 → v0~vN 비교 타당.
- **seen/unseen**(⑤): test를 평가 시점에 사후 분할. test 도면의 program 지문(방 타입 multiset)이 train에 있었나로 → **seen 487 / unseen 31**. *새 split이 아니라 진단 렌즈.* seen=암기·보간, unseen=진짜 일반화.
- **규제루프**(④ on): 생성 → 법규 위반 시 자동보정 → legal 0.94→1.00.
- **temperature**(④): val 599로 선택(`sweep_temperature`), test엔 고정값 적용.
- **지표**: `integrity`(위상 R1~R5) · `legal`(채광 등) · `adj_L1`(인접 L1, 낮을수록 GT 근접) · `diversity` · `novelty`.

## 5-A. 평가지표와 그 근거 (Why these metrics — 발표·논문 디펜스용)

> "왜 이 지표인가 / 왜 이렇게 집계했나 / 무엇을 못 보나"에 답하기 위한 절. 심사·발표에서 그대로 인용.

**큰 틀 — 지표를 3가지 역할로 나눈다(이게 방어 논리의 뼈대):**

| 역할 | 지표 | 의미 |
|---|---|---|
| ① 핵심 변별(성능 판정) | 매크로 adj_L1 · unseen adj_L1 | 버전(데이터 조합) 간 진짜 우열을 드러냄 |
| ② 메커니즘 입증(Neuro-Symbolic) | 법규(off→on) | 규제루프(Symbolic)의 기여 정량 증명 |
| ③ 가드레일(부정행위 방지) | 무결성 · 다양성 · 신규성 | 이득이 모드붕괴·암기 같은 꼼수가 아님을 보증 |

> 핵심 방어: *우열은 adj_L1로 가리되, 그 이득이 꼼수가 아님을 가드레일로 증명한다.*

### ① 핵심 변별 지표

**인접 L1 (adj_L1)** — 낮을수록 좋음
- **정의 (계산 절차 — `eval_gen._metrics`)**: **실제 도면 vs 생성 도면**을 *분포 수준*에서 비교.
  1. test의 각 **실제 도면**(이미 방-관계 그래프)과, 그 도면의 방 구성(program)으로 생성한 **생성 도면**을 각각 그래프로 둔다.
  2. 각 그래프에서 **연결된 방-쌍**을 추출(통행 via=door/open 등 `CONNECT`만, 외부 노드 제외) — 거실–주방, 침실–욕실, 현관–거실 …
  3. 전체 test에서 방-쌍별 등장 빈도를 센다(실제·생성 각각 누적).
  4. 확률분포로 정규화: **P_real**(실제 인접 분포) · **P_gen**(생성 인접 분포).
  5. L1 거리: **adj_L1 = Σ|P_gen − P_real|** (0~2).
  6. 낮을수록 실제 도면의 인접 패턴을 더 잘 재현.
  - *공정성: 실제·생성 모두 **동일 인접 정의**(같은 `CONNECT` 필터)로 추출. 생성은 실제 도면의 방 구성별 1:1로 만들어 같은 방 집합끼리 비교. **P_real은 동결 균형 test로 고정** → 버전마다 P_gen만 변해 같은 표적과의 거리를 재므로 버전 비교가 타당.*
- **왜 이 지표**: 이 단계 출력은 **위상(관계 그래프)**, 좌표가 아님 → 평가도 *"방들이 실제처럼 연결되었나"*. 한국 집 특징(거실 허브·침실–욕실 인접·발코니 패턴)을 **분포 수준**에서 재현하는지 정량화.
- **왜 L1**(KL·L2 아님): 해석 직관적(확률 차이 절대합, 0~2 유계)·0분모 문제 없음(KL 약점)·과대/과소예측 대칭.
- **디펜스**: ⟨왜 그림 품질이 아니라 인접?⟩ 좌표 도면은 다음 단계. 인접이 틀리면(안방을 욕실 통해 감) 아무리 예뻐도 무용 → 위상 충실도가 선결조건. ⟨왜 그래프 일대일 일치가 아니라 분포?⟩ 같은 방 구성에 타당한 배치는 여럿 → 일대일 요구는 정당한 다양성을 벌함. 분포 일치가 옳은 목표.
- **⚠️ 한계(필독)**: 방 타입이 **역할 무구분**(화장실=부부/공용 미분리, 침실=안방/손님방 미분리)이라, adj_L1이 역할 위상 오류(안방에 공용화장실 등)를 **못 잡는다** → 현 수치는 역할 수준에서 관대·상향편향 가능. 문화 의존적 한계 포함 상세는 **§5-1**.

**unseen adj_L1** — 낮을수록 좋음
- **정의**: test를 *학습에서 본 방조합 / 못 본 방조합*으로 사후 분할, **못 본 조합**의 adj_L1.
- **왜**: 학습 program만 재현하면 무용(실사용=새 요구). 못 본 조합에서 인접 규칙을 일반화하는지 = **암기 vs 진짜 학습**.
- **디펜스**: ⟨test가 이미 held-out 아닌가?⟩ test 그래프가 학습과 *같은 방구성*일 수 있음. seen/unseen은 방구성 신규성까지 가르는 더 엄격한 일반화 검증.

**집계 — 매크로(주거형태 동등가중) vs 마이크로**
- **마이크로**: 전체 test 풀에서 adj_L1 1회 → APT(94%)가 지배.
- **매크로**: APT/DEH/ROW 각각 adj_L1 후 **동등 평균**.
- **왜 매크로가 소버린 헤드라인**: 목적은 *전 주거형태에 작동하는* AI. 마이크로면 APT만 잘하고 DEH/ROW 실패해도 좋아 보임(다수에 묻힘). 매크로는 유형별 책임을 동등 부과 → 소수형태 실패를 드러냄(불균형 분류의 macro-F1과 같은 원리).
- **디펜스**: ⟨실제론 APT가 다수인데 왜 동등가중?⟩ 목표가 소수형태(단독·연립)까지 포괄하는 소버린 커버리지라서. 유병률 가중(마이크로)은 소수형태 방치를 제도화함. 둘 다 보고하되 헤드라인=매크로(목표와 일치).

### ② 메커니즘 입증 지표

**법규 (legal)** — 높을수록 좋음 (off→on)
- **정의**: 생성 위상의 건축법규(채광 등) 통과율. 규제루프 off(생성만) vs on(위반 자동보정).
- **왜**: 한국형 소버린 AI는 국내 법규 준수가 필수. off→on 변화가 **Neuro-Symbolic의 'Symbolic'(자기교정) 기여**를 정량 입증.
- **디펜스**: ⟨왜 규제루프를 분리?⟩ 신경망(Neuro)=충실도, 자기교정(Symbolic)=준법 분담. off→on 폭이 *Symbolic이 실제로 한 일*. 논문 ablation의 핵심.

### ③ 가드레일 지표 (점수의 정당성)

- **무결성(integrity)** ↑ — 구조 규칙(R1~R5: 연결성·현관 존재) 통과율. 출력의 구조적 유효성 보증(대개 100% → 변별 아닌 바닥).
- **다양성(diversity)** ↑ — 서로 다른 그래프 비율. *adj_L1이 낮은 게 같은 답만 찍어서(모드붕괴) 아님*을 증명.
- **신규성(novelty)** ↑ — 학습에 없던 구조 비율. *학습 그래프를 베껴온 게 아님* 증명.

> **정직한 핵심(디펜스에서 먼저 밝힘)**: 실제로 변별되는 건 **adj_L1**뿐, 무결성·다양성·신규성은 거의 평평(~100%/~1.0)·법규는 코퍼스별로만 갈림. 이는 약점이 아니라 *"우열은 충실도로 가리고, 나머지는 그 이득이 꼼수가 아님을 보증하는 장치"* — 오히려 강한 방어.

### 선택·객관성 규칙 (pre-register)
1. **단일 고정 벤치마크** — AI-Hub 균형 동결 test(APT·DEH·ROW 동등), 전 버전 공유. 비교 타당성의 전제.
2. **다시드(5) → 평균±표준편차** — 한 번의 운이 아닌 기대성능+변동성.
3. **선택은 val, 측정은 test 1회** — test로 시드/모델 고르면 누수(부정). 분리 엄수.
4. **유의성으로 우위 선언** — 차이가 표준편차(노이즈) 안이면 "동률". 눈대중 금지.
5. **대표 모델(시드)** = val 최저 adj_L1 시드 → 그 시드 test 1회 보고(누수 0).
6. **패러다임 비교** — 데이터 조합(합쳐서 한 번) vs 전이학습(사전학습→파인튜닝)을 같은 test로 비교 → 계획서 가정이 아니라 *결과*로 판정.

## 6. 결과 채택 규칙 (드리프트 방지의 핵심)

## 4. 해석·결론 [2026-06-05]
1. **반전 — 균형 벤치마크에선 신경망 > 규칙기반.** 규칙기반은 데이터 많은 APT에 과적합, 소수 유형(DEH/ROW) 실패. 신경망은 유형 강건. 옛 "규칙기반 최강" 결론은 *APT지배 평가의 산물*. **소버린 AI엔 신경망.**
2. **V2V 확장(v2)은 여전히 충실도·법규 악화.** 전체 0.088→0.114, **법규(off) 90→42%**, unseen 0.173→0.214. 규제루프 on으로 법규는 100% 복구. *수량(+375 use)≠품질* 재확인([[v2v-expansion-hurts-generation]]).
3. **사전학습 무익(전 변형, 5시드 확정).** CubiCasa ≈ 중립(v0 0.188→0.189, v2 0.193→0.186), RPLAN(v3) 0.200·결합(v4) 0.193은 **무사전학습보다 악화**. 마이크로 eval도 무사전학습 0.088이 전 변형(0.095~0.110) 우수. *예비 "RPLAN 최선 0.178"은 단일시드 잡음.* → **글로벌 사전학습보다 균형 한국 데이터가 핵심**(소버린 논지 지지).
4. **type조건이 최대 레버(§7).** 주거형태 조건화 매크로 **0.123** — 사전학습·코퍼스 어떤 조합보다 큼. 소수형태(ROW +0.071, DEH +0.033)에서 격차를 메움, 다수 APT는 무변(+0.003).
5. 신경망 의의 = **유형 강건성 + unseen 일반화**(규칙기반은 seen-APT 특화).

### 5-1. 방 타입의 역할(role) 무구분 — adj_L1의 근본 한계 ⚠️ (중요)

**현상.** 방 타입(`config.SPACE_CLASSES`)이 **역할을 구분하지 않는다.** `공간_침실` 하나뿐(안방/master ↔ 손님방·작은방/guest 구분 없음), `공간_화장실` 하나뿐(부부전용/private ↔ 공용/public 구분 없음). 소스(AI-Hub) 라벨 자체가 역할 미부여.

**왜 문제인가 — 한국 아파트의 역할 위상은 실제 규칙이다.**
- **private bathroom(부부화장실)** ↔ 안방(부부 침실) 전용 인접
- **public bathroom(공용화장실)** ↔ 거실·복도 등 공용 동선에서 접근
- (확장) 안방 ↔ 드레스룸 인접·독립 동선 등
이는 취향이 아니라 한국 평면의 **위상 규칙**. 모델이 *"안방에 공용화장실을 붙이고 손님이 안방을 통해 화장실로 가는"* 평면을 만들어도, 타입이 둘 다 `화장실`이라 **위상상 동일**하게 취급된다.

**adj_L1에 미치는 영향(핵심).** 화장실을 한 타입으로 합치면 adj_L1은 "침실–화장실" 쌍 하나로만 세므로 **역할 오배치를 못 잡는다.**
> *제대로 설계된 adj_L1이라면 역할 위상이 틀릴 때 **나빠져야** 한다. 나빠지지 않는다면 그 adj 정의가 **너무 거친** 것이다.*
→ 따라서 현재 adj_L1은 역할 위상 오류에 **관대(낙관적)**. 실제 한국 평면 충실도는 보고치보다 낮을 수 있고, 버전 간 차이도 역할 수준에선 드러나지 않을 수 있다(현 수치의 상향 편향 가능성).

**문화 의존성(연구 범위 한계).** 역할 위상은 **문화권마다 다르다** — 한국·유럽·중국·일본 주거문화의 안방/화장실/동선 규칙이 상이(예: 한국의 안방-부부화장실 결합은 보편적이나 타 문화권은 다름). 본 연구는 **한국 AI-Hub 한정, 그마저 역할 미구분.** 문화권별 위상 규칙 모델링은 본 연구 범위 밖(미래 과제). 글로벌(CubiCasa·RPLAN)을 합쳐도 역할·문화 위상이 어긋나 국내 충실도에 무익/악화한 §6 결과도 이와 일관.

**부분 단서(현재 미활용).** 드레스룸(통상 안방 동반)·객체 라벨(`OBJECT_CLASSES`: 변기·세면대·욕조 등)로 화장실 역할을 *추론*할 여지가 있으나 현재 타입 분할엔 반영 안 됨.

**향후 개선 경로.** ① 역할-aware 재타이핑(안방/손님방, 부부/공용 화장실) 또는 객체·인접 맥락으로 역할 추론 → ② adj_L1을 **역할 수준으로 세분화** → ③ 문화권별 위상 규칙(SWRL 등)으로 평가·규제 확장. 그러면 더 엄격하고 문화가 반영된 충실도 측정이 가능. (현 한계를 디펜스에서 *명시적으로 선언*하는 것이 정직성·후속연구 동기 측면에서 유리.)

| **매크로** | **0.123±0.011** | 0.159±0.016 | **+0.036** |

- **소수형태에서 큰 이득**(ROW +0.071·DEH +0.033), 다수 APT는 무변(+0.003) — 조건화가 *과소대표 유형의 격차를 메운다*. 정확히 소버린 AI가 노리는 패턴.
- 조건 ON 매크로 **0.123**은 사전학습/코퍼스 어떤 조합(최선 0.186)보다 큰 폭으로 앞섬 → **type조건이 단일 최대 레버.**
- v3/v4(set-transformer-v2)와 **완전 격리**(arch·파일명·run_id 분리) — 실행 중 영향 0(ADR-0001).

## 8. 데이터셋 조합 매트릭스 (v1~v7, combine) — 합쳐서 한 번 학습 [2026-06-06]

> **현재 단계 = 데이터셋 조합 실험**(전이학습 아님). 여러 데이터셋을 *합쳐 한 데이터셋으로 한 번에 학습*(`train_combine.py`)해 **어떤 조합이 최고인지** 비교. 각 5시드, 동결 균형 AI-Hub test(전 버전 공유). 정본=`runs/index.jsonl`(시드 정규화 `scripts/normalize_ledger.py` 적용), 조회 `scripts/show_combine_results.py`.

**버전 정의:** v0=AI-Hub 7,101(dual 클린·기준) · v1=AI-Hub 20,828 · v2=+CubiCasa 3,028 · v3=+RPLAN 80,371 · v4=+둘다 · v5=RPLAN만 · v6=CubiCasa만 · v7=RPLAN+CubiCasa(v5~7=글로벌만).

| 버전 | 데이터 조합 | 매크로↓ | 마이크로↓ | unseen↓ | 법규(off→on) |
|---|---|---|---|---|---|
| **v0** | AI-Hub 7,101 (클린) | 0.188 | **0.088** | **0.173** | 89→100% |
| v1 | AI-Hub 20,828 | 0.186 | 0.112 | 0.215 | 60→100% |
| v2 | + CubiCasa | 0.201 | 0.118 | 0.214 | 42→100% |
| v3 | + RPLAN | 0.189 | 0.112 | 0.216 | 0→100% |
| v4 | + CubiCasa + RPLAN | 0.190 | 0.116 | 0.203 | 0→100% |
| v5 | RPLAN만 (글로벌) | 0.496 | 0.494 | 0.502 | 0→100% |
| v6 | CubiCasa만 (글로벌) | 0.760 | 0.697 | 0.718 | 0→100% |
| v7 | RPLAN+CubiCasa (글로벌) | 0.505 | 0.480 | 0.477 | 0→100% |

**결론:**
1. **클린 AI-Hub(v0)만으로 최선.** 마이크로 0.088이 전 조합 압도(나머지 ≥0.112). 매크로는 v0≈v1(0.188/0.186, 노이즈 내 동률)이나 마이크로·unseen에서 v0 우위.
2. **AI-Hub 양을 늘려도(v1=20,828, V2V 확장) 개선 없음** — 매크로 동률, 마이크로·unseen 악화(V2V 노이즈). *수량≠품질* 재확인.
3. **글로벌을 합쳐도(v2·v3·v4) 무익** — 매크로 0.19대, 마이크로 0.11~0.12로 v0(0.088)보다 나쁨. 조합이 도움 안 됨.
4. **글로벌만(v5·v6·v7)은 국내 test서 처참**(매크로 0.50~0.76) → **글로벌↔국내 도메인 격차**. 한국 데이터 없이는 한국 도면 불가 = **소버린 데이터의 필요성을 데이터가 증명**. (방분포 §대시보드: RPLAN/CubiCasa엔 발코니·실외기실·현관이 빈약 — 한국 고유 패턴 결여가 원인.)
5. **규제루프(Symbolic) 가치 재확인** — 글로벌/RPLAN을 섞으면 사전(off) 법규가 0%로 폭락(글로벌 데이터는 한국 채광법 패턴 결여)하나, 규제루프 on이 전부 100%로 복구.

**패러다임 종합(조합 vs 전이학습):** 글로벌 증강은 **합치기(조합, §8)로도, 사전학습→파인튜닝(전이, §6)으로도 무익**. 둘 다 클린 AI-Hub만 못함. → 계획서의 "글로벌 사전학습 유익" 가정은 **데이터로 반증**. **균형 잡힌 클린 한국(소버린) 데이터가 핵심.** 단, §5-1 한계(역할·문화 위상 미반영)로 adj_L1이 역할 오류엔 관대 — 향후 역할-aware 평가로 재검증 여지.

## 9. 모델 용량 ablation (v0cap2x) — 파라미터를 키우면? [2026-06-06]

> epochs뿐 아니라 **모델 파라미터(용량)**도 성능에 영향. 기본값은 전 버전(v0~v7) 통일했고, 별도로 **같은 v0 데이터(AI-Hub 클린)에 모델만 2배** 키워 비교. `scripts/run_capacity.py`, 5시드.

| 모델 | embedding·layers·heads·FFN | APT | DEH | ROW | 매크로↓ | 마이크로↓ | unseen↓ |
|---|---|---|---|---|---|---|---|
| v0 (기본) | 48·2·4·96 | 0.137 | 0.195 | 0.233 | 0.188 | 0.088 | 0.173 |
| **v0cap2x (2배)** | 96·4·8·192 | 0.124 | 0.183 | **0.191** | **0.166** | 0.084 | 0.176 |

**결론:** **모델 용량을 키우면 개선됨**(매크로 0.188→0.166). 특히 **소수형태 ROW(연립)에서 −0.042로 최대**, DEH·APT도 소폭↓. unseen은 ≈동일. → *기본(작은) 모델은 소수 주거형태를 담기엔 용량 부족*이었고, 키우니 균형 성능이 올랐다. **데이터 조합(§8)·type조건(§7)에 더해 모델 용량도 소수형태 개선의 레버.** (예비 가설 "소량 데이터라 용량 무익"은 **반증** — macro/소수형태에서 분명한 이득.) 단 §5-1 한계는 동일 적용.
