## 1. 파이프라인 (한눈에)

```
[글로벌 사전학습셋]            [한국형 파인튜닝셋]         [평가: AI-Hub 동결 test]
 CubiCasa/RPLAN  ──사전학습──▶  AI-Hub(v0)  ──파인튜닝──▶  test 518장 (전 버전 공유)
   (선택)          50ep          100ep                       │
                                  │                          ├─ 규제루프 off/on
                              val 599로 temperature 선택       └─ seen 487 / unseen 31 로 분할 진단
```

- 코드: 학습 `train_gen.train()` · 평가 `eval_gen.evaluate_version()` · 일반화 `eval_gen.generalization_diag()`
  · 집계 `experiments.agg_summary()` · 오케스트레이션 `scripts/run_matrix.sh`.

## 2. 직교 5축 (이 5개를 섞지 말 것 — 혼동의 뿌리였음)

| 축 | 값 | 의미 | 결정 위치 |
|---|---|---|---|
| **① 데이터버전** | v0·v1·v2·v3 | 학습 데이터 조합(AI-Hub/+보정/+CubiCasa/+RPLAN) | DATASET_DESIGN · recipe |
| **② 생성기** | 규칙기반(알고리즘) · 신경망(set-transformer) | 통계 baseline vs 학습모델. **신경망은 모델 1종** | `eval_gen` · `train_gen` |
| **③ 학습레짐** | 미배치 → 배치 | 학습 **절차 성숙**(모델 동일, "버전" 아님) | `train_gen.train(batch_size)` |
| **④ 추론/규제** | temperature · 규제루프 on/off | 다양성 조절 · 법규 자동보정 | `eval_gen` · `gen_loop` |
| **⑤ 평가렌즈** | 전체 · seen · unseen | 같은 test를 보는 각도 | `eval_gen.generalization_diag` |

> ⚠️ "v1/v2"는 ①(데이터)에서만 쓴다. ③(학습레짐)을 "set-transformer-v1/v2"로 부르던 건 **폐기**(이름 충돌).
> 신경망 라벨은 버전꼬리표 없이 `신경망(set-transformer)` 하나.

## 3. 모델 — set-transformer (`train_gen._build_model`, EdgeModel)

방을 **순서 무관 집합**으로 보고 어떤 방끼리 무엇으로 연결되는지 예측하는 **링크예측기**.

- 방 타입 → `Embedding(48)` → `TransformerEncoder`(d_model 48, 2층, 4헤드, ffn 96, dropout 0) → 방별 맥락 `h` + 전역 program 맥락 `g`(평균).
- 방 쌍 (i,j): `[h_i+h_j, |h_i−h_j|, g]` → 두 헤드: **edge**(연결 여부) + **via**(연결 종류: door/open/balcony/…).
- 입력 = program(방 타입 집합), 출력 = 인접 그래프. ("Set Transformer" 논문의 ISAB/PMA가 아니라 일반 TransformerEncoder의 집합 self-attention.)

## 4. 학습 절차 — 두 모듈 (조합학습 vs 전이학습, 분리)

- **현재 단계 = 데이터셋 조합학습** (`train_combine.train`): 여러 소스를 **합쳐 한 데이터셋으로 한 번에 100ep 학습**(전이학습 아님). 어떤 조합이 최고인지 비교. → [[combine-matrix-running]]
- **다음 단계 = 전이학습** (`train_gen.train`): `--pretrain global_*`(50ep) → `--finetune`(100ep). **별도 모듈·메뉴**(섞지 않음). noPretrain은 파인튜닝 100ep만(동일 예산 공정 비교).
- **공유**: 모델 구조(set-transformer)·featurize·평가지표(`_metrics`)는 동일 → 공정 비교. 학습 루프만 모듈별 보유.
- **배치학습**: 가변 방수를 패딩+어텐션마스크로 한 배치(64)에 쌓아 통과 + 특징 1회 사전계산(미배치 대비 수배 가속).
- **손실 = 전 방-쌍 BCE(연결여부) + 양성쌍 via CE.** *배치 레짐은 음성 서브샘플링 없이 전 쌍 사용*(옛 `neg_ratio`는 미배치 잔재). 최적화 Adam(lr 1e-3), 시드 고정(`exp.seed_everything`).
- **재현**: run_id = `gen-<버전>-neural-<arch>-<pretrain|noPretrain>-seed<N>`. **각 학습의 정확한 파라미터는 `runs/<run_id>/meta.json`의 `condition`에 전량 보존**(checkpoint.pt·train.log 함께). 체크포인트는 git 제외(시드+코드로 재생성), 메타·지표·원장만 git 추적.

### 4-A. 학습 사양 (Training spec — 논문 인용용)

| 항목 | 값 |
|---|---|
| 모델 | set-transformer 링크예측기 (일반 TransformerEncoder의 집합 self-attention) |
| 임베딩 | 48차원 |
| 인코더 | 2층 · 4헤드 · FFN 96 · dropout 0 |
| 출력 헤드 | edge(연결여부, BCE) + via(연결종류: door/open/balcony, CE) |
| 입력 → 출력 | program(방 타입 집합) → 방-쌍 인접 그래프(위상) |
| 손실 | 전 방-쌍 BCE + 양성쌍 via CE (음성 서브샘플 없음) |
| 최적화 | Adam, lr 1e-3 |
| 배치 | 64 (패딩+어텐션마스크, 크기 버킷팅) |
| 에폭 | 100 (조합 단일학습 / 전이학습 파인튜닝); 전이학습 사전학습 50 |
| 시드 | 42 · 1 · 2 · 3 · 4 (5시드 → 평균±표준편차) |
| 생성 온도 T | eval=모델 기본 · 일반화/dwelling 진단=0.85 (*논문 보고 시 통일 권장*) |
| 평가셋 | AI-Hub 균형 동결 test(APT·DEH·ROW 동등, 전 버전 공유) |
| 평가 항목 | eval(전체) · seen/unseen(일반화) · dwelling(주거형태) · 규제루프 off/on |
| 재현 소스 | `runs/<run_id>/meta.json`(condition 전체) · checkpoint.pt · train.log · `runs/index.jsonl`(원장) |

> 논문 작성 시: 표의 값은 코드 기본값이며, **버전·시드별 실제 사용값은 `runs/<run_id>/meta.json`이 정본**(여기서 발췌). 온도 T는 현재 eval/진단이 달라 보고 전 통일 필요.

## 5. 평가 (`eval_gen`)

- **벤치마크 앵커 = AI-Hub 동결 test 518장**(`_frozen_test.json`, v0에서 정의·전 버전 공유). 이것만 불변 → v0~vN 비교 타당.
- **seen/unseen**(⑤): test를 평가 시점에 사후 분할. test 도면의 program 지문(방 타입 multiset)이 train에 있었나로 → **seen 487 / unseen 31**. *새 split이 아니라 진단 렌즈.* seen=암기·보간, unseen=진짜 일반화.
- **규제루프**(④ on): 생성 → 법규 위반 시 자동보정 → legal 0.94→1.00.
- **temperature**(④): val 599로 선택(`sweep_temperature`), test엔 고정값 적용.
- **지표**: `integrity`(위상 R1~R5) · `legal`(채광 등) · `adj_L1`(인접 L1, 낮을수록 GT 근접) · `diversity` · `novelty`.

## 5-A. 평가지표와 그 근거 (Why these metrics — 발표·논문 디펜스용)

> "왜 이 지표인가 / 왜 이렇게 집계했나 / 무엇을 못 보나"에 답하기 위한 절. 심사·발표에서 그대로 인용.

**큰 틀 — 지표를 3가지 역할로 나눈다(이게 방어 논리의 뼈대):**

| 역할 | 지표 | 의미 |
|---|---|---|
| ① 핵심 변별(성능 판정) | 매크로 adj_L1 · unseen adj_L1 | 버전(데이터 조합) 간 진짜 우열을 드러냄 |
| ② 메커니즘 입증(Neuro-Symbolic) | 법규(off→on) | 규제루프(Symbolic)의 기여 정량 증명 |
| ③ 가드레일(부정행위 방지) | 무결성 · 다양성 · 신규성 | 이득이 모드붕괴·암기 같은 꼼수가 아님을 보증 |

> 핵심 방어: *우열은 adj_L1로 가리되, 그 이득이 꼼수가 아님을 가드레일로 증명한다.*

### ① 핵심 변별 지표

**인접 L1 (adj_L1)** — 낮을수록 좋음
- **정의 (계산 절차 — `eval_gen._metrics`)**: **실제 도면 vs 생성 도면**을 *분포 수준*에서 비교.
  1. test의 각 **실제 도면**(이미 방-관계 그래프)과, 그 도면의 방 구성(program)으로 생성한 **생성 도면**을 각각 그래프로 둔다.
  2. 각 그래프에서 **연결된 방-쌍**을 추출(통행 via=door/open 등 `CONNECT`만, 외부 노드 제외) — 거실–주방, 침실–욕실, 현관–거실 …
  3. 전체 test에서 방-쌍별 등장 빈도를 센다(실제·생성 각각 누적).
  4. 확률분포로 정규화: **P_real**(실제 인접 분포) · **P_gen**(생성 인접 분포).
  5. L1 거리: **adj_L1 = Σ|P_gen − P_real|** (0~2).
  6. 낮을수록 실제 도면의 인접 패턴을 더 잘 재현.
  - *공정성: 실제·생성 모두 **동일 인접 정의**(같은 `CONNECT` 필터)로 추출. 생성은 실제 도면의 방 구성별 1:1로 만들어 같은 방 집합끼리 비교. **P_real은 동결 균형 test로 고정** → 버전마다 P_gen만 변해 같은 표적과의 거리를 재므로 버전 비교가 타당.*
- **왜 이 지표**: 이 단계 출력은 **위상(관계 그래프)**, 좌표가 아님 → 평가도 *"방들이 실제처럼 연결되었나"*. 한국 집 특징(거실 허브·침실–욕실 인접·발코니 패턴)을 **분포 수준**에서 재현하는지 정량화.
- **왜 L1**(KL·L2 아님): 해석 직관적(확률 차이 절대합, 0~2 유계)·0분모 문제 없음(KL 약점)·과대/과소예측 대칭.
- **디펜스**: ⟨왜 그림 품질이 아니라 인접?⟩ 좌표 도면은 다음 단계. 인접이 틀리면(안방을 욕실 통해 감) 아무리 예뻐도 무용 → 위상 충실도가 선결조건. ⟨왜 그래프 일대일 일치가 아니라 분포?⟩ 같은 방 구성에 타당한 배치는 여럿 → 일대일 요구는 정당한 다양성을 벌함. 분포 일치가 옳은 목표.
- **⚠️ 한계(필독)**: 방 타입이 **역할 무구분**(화장실=부부/공용 미분리, 침실=안방/손님방 미분리)이라, adj_L1이 역할 위상 오류(안방에 공용화장실 등)를 **못 잡는다** → 현 수치는 역할 수준에서 관대·상향편향 가능. 문화 의존적 한계 포함 상세는 **§5-1**.

**unseen adj_L1** — 낮을수록 좋음
- **정의**: test를 *학습에서 본 방조합 / 못 본 방조합*으로 사후 분할, **못 본 조합**의 adj_L1.
- **왜**: 학습 program만 재현하면 무용(실사용=새 요구). 못 본 조합에서 인접 규칙을 일반화하는지 = **암기 vs 진짜 학습**.
- **디펜스**: ⟨test가 이미 held-out 아닌가?⟩ test 그래프가 학습과 *같은 방구성*일 수 있음. seen/unseen은 방구성 신규성까지 가르는 더 엄격한 일반화 검증.

**집계 — 매크로(주거형태 동등가중) vs 마이크로**
- **마이크로**: 전체 test 풀에서 adj_L1 1회 → APT(94%)가 지배.
- **매크로**: APT/DEH/ROW 각각 adj_L1 후 **동등 평균**.
- **왜 매크로가 소버린 헤드라인**: 목적은 *전 주거형태에 작동하는* AI. 마이크로면 APT만 잘하고 DEH/ROW 실패해도 좋아 보임(다수에 묻힘). 매크로는 유형별 책임을 동등 부과 → 소수형태 실패를 드러냄(불균형 분류의 macro-F1과 같은 원리).
- **디펜스**: ⟨실제론 APT가 다수인데 왜 동등가중?⟩ 목표가 소수형태(단독·연립)까지 포괄하는 소버린 커버리지라서. 유병률 가중(마이크로)은 소수형태 방치를 제도화함. 둘 다 보고하되 헤드라인=매크로(목표와 일치).

### ② 메커니즘 입증 지표

**법규 (legal)** — 높을수록 좋음 (off→on)
- **정의**: 생성 위상의 건축법규(채광 등) 통과율. 규제루프 off(생성만) vs on(위반 자동보정).
- **왜**: 한국형 소버린 AI는 국내 법규 준수가 필수. off→on 변화가 **Neuro-Symbolic의 'Symbolic'(자기교정) 기여**를 정량 입증.
- **디펜스**: ⟨왜 규제루프를 분리?⟩ 신경망(Neuro)=충실도, 자기교정(Symbolic)=준법 분담. off→on 폭이 *Symbolic이 실제로 한 일*. 논문 ablation의 핵심.

### ③ 가드레일 지표 (점수의 정당성)

- **무결성(integrity)** ↑ — 구조 규칙(R1~R5: 연결성·현관 존재) 통과율. 출력의 구조적 유효성 보증(대개 100% → 변별 아닌 바닥).
- **다양성(diversity)** ↑ — 서로 다른 그래프 비율. *adj_L1이 낮은 게 같은 답만 찍어서(모드붕괴) 아님*을 증명.
- **신규성(novelty)** ↑ — 학습에 없던 구조 비율. *학습 그래프를 베껴온 게 아님* 증명.

> **정직한 핵심(디펜스에서 먼저 밝힘)**: 실제로 변별되는 건 **adj_L1**뿐, 무결성·다양성·신규성은 거의 평평(~100%/~1.0)·법규는 코퍼스별로만 갈림. 이는 약점이 아니라 *"우열은 충실도로 가리고, 나머지는 그 이득이 꼼수가 아님을 보증하는 장치"* — 오히려 강한 방어.

### 선택·객관성 규칙 (pre-register)
1. **단일 고정 벤치마크** — AI-Hub 균형 동결 test(APT·DEH·ROW 동등), 전 버전 공유. 비교 타당성의 전제.
2. **다시드(5) → 평균±표준편차** — 한 번의 운이 아닌 기대성능+변동성.
3. **선택은 val, 측정은 test 1회** — test로 시드/모델 고르면 누수(부정). 분리 엄수.
4. **유의성으로 우위 선언** — 차이가 표준편차(노이즈) 안이면 "동률". 눈대중 금지.
5. **대표 모델(시드)** = val 최저 adj_L1 시드 → 그 시드 test 1회 보고(누수 0).
6. **패러다임 비교** — 데이터 조합(합쳐서 한 번) vs 전이학습(사전학습→파인튜닝)을 같은 test로 비교 → 계획서 가정이 아니라 *결과*로 판정.

## 6. 결과 채택 규칙 (드리프트 방지의 핵심)

1. **단일 소스**: 모든 결과는 `runs/index.jsonl` → `experiments.agg_summary()` 한 곳에서 집계. 대시보드 §3·§5·EXPERIMENTS.md가 이걸 공유(숫자 어긋남 불가).
2. **수렴·다중시드만 채택**: 시드 1개·미수렴 탐색본은 결과로 보지 않는다.
3. **개발 부산물 폐기**: 미배치(`set-transformer-v1`, 30ep·1시드)는 `experiments.RETIRED_ARCH`로 집계 제외. git/runs 원본엔 이력 보존.
4. **재학습 시 최종값만 남김**: 데이터 늘려 재학습하면 같은 표의 해당 버전 행을 **갱신**(중간값 누적 금지).

## 4. 해석·결론 [2026-06-05]
1. **반전 — 균형 벤치마크에선 신경망 > 규칙기반.** 규칙기반은 데이터 많은 APT에 과적합, 소수 유형(DEH/ROW) 실패. 신경망은 유형 강건. 옛 "규칙기반 최강" 결론은 *APT지배 평가의 산물*. **소버린 AI엔 신경망.**
2. **V2V 확장(v2)은 여전히 충실도·법규 악화.** 전체 0.088→0.114, **법규(off) 90→42%**, unseen 0.173→0.214. 규제루프 on으로 법규는 100% 복구. *수량(+375 use)≠품질* 재확인([[v2v-expansion-hurts-generation]]).
3. **사전학습 무익(전 변형, 5시드 확정).** CubiCasa ≈ 중립(v0 0.188→0.189, v2 0.193→0.186), RPLAN(v3) 0.200·결합(v4) 0.193은 **무사전학습보다 악화**. 마이크로 eval도 무사전학습 0.088이 전 변형(0.095~0.110) 우수. *예비 "RPLAN 최선 0.178"은 단일시드 잡음.* → **글로벌 사전학습보다 균형 한국 데이터가 핵심**(소버린 논지 지지).
4. **type조건이 최대 레버(§7).** 주거형태 조건화 매크로 **0.123** — 사전학습·코퍼스 어떤 조합보다 큼. 소수형태(ROW +0.071, DEH +0.033)에서 격차를 메움, 다수 APT는 무변(+0.003).
5. 신경망 의의 = **유형 강건성 + unseen 일반화**(규칙기반은 seen-APT 특화).

### 5-1. 방 타입의 역할(role) 무구분 — adj_L1의 근본 한계 ⚠️ (중요)

**현상.** 방 타입(`config.SPACE_CLASSES`)이 **역할을 구분하지 않는다.** `공간_침실` 하나뿐(안방/master ↔ 손님방·작은방/guest 구분 없음), `공간_화장실` 하나뿐(부부전용/private ↔ 공용/public 구분 없음).

**원인이 소스별로 다름(2026-06-06 검증):**
- **AI-Hub(소버린 소스)는 애초에 역할 미주석** — 실제 방타입이 침실·화장실뿐(안방·욕실 없음, 데이터 직접 확인). → 소버린 모델은 *없는 라벨을 복원할 수 없음*(근본 제약).
- **RPLAN은 역할 구분이 있었음** — masterroom·childroom·secondroom·guestroom(침실 계열)을 따로 분류하나, 통합 온톨로지(`adapters/common.py`)에서 모두 `공간_침실`로 **합쳐 소실**. → *있던 정보를 통합 과정에서 버림*.
- CubiCasa는 Bedroom 단일(구분 없음).

**왜 문제인가 — 한국 아파트의 역할 위상은 실제 규칙이다.**
- **private bathroom(부부화장실)** ↔ 안방(부부 침실) 전용 인접
- **public bathroom(공용화장실)** ↔ 거실·복도 등 공용 동선에서 접근
- (확장) 안방 ↔ 드레스룸 인접·독립 동선 등
이는 취향이 아니라 한국 평면의 **위상 규칙**. 모델이 *"안방에 공용화장실을 붙이고 손님이 안방을 통해 화장실로 가는"* 평면을 만들어도, 타입이 둘 다 `화장실`이라 **위상상 동일**하게 취급된다.

**adj_L1에 미치는 영향(핵심).** 화장실을 한 타입으로 합치면 adj_L1은 "침실–화장실" 쌍 하나로만 세므로 **역할 오배치를 못 잡는다.**
> *제대로 설계된 adj_L1이라면 역할 위상이 틀릴 때 **나빠져야** 한다. 나빠지지 않는다면 그 adj 정의가 **너무 거친** 것이다.*
→ 따라서 현재 adj_L1은 역할 위상 오류에 **관대(낙관적)**. 실제 한국 평면 충실도는 보고치보다 낮을 수 있고, 버전 간 차이도 역할 수준에선 드러나지 않을 수 있다(현 수치의 상향 편향 가능성).

**문화 의존성(연구 범위 한계).** 역할 위상은 **문화권마다 다르다** — 한국·유럽·중국·일본 주거문화의 안방/화장실/동선 규칙이 상이(예: 한국의 안방-부부화장실 결합은 보편적이나 타 문화권은 다름). 본 연구는 **한국 AI-Hub 한정, 그마저 역할 미구분.** 문화권별 위상 규칙 모델링은 본 연구 범위 밖(미래 과제). 글로벌(CubiCasa·RPLAN)을 합쳐도 역할·문화 위상이 어긋나 국내 충실도에 무익/악화한 §6 결과도 이와 일관.

**부분 단서(현재 미활용).** 드레스룸(통상 안방 동반)·객체 라벨(`OBJECT_CLASSES`: 변기·세면대·욕조 등)로 화장실 역할을 *추론*할 여지가 있으나 현재 타입 분할엔 반영 안 됨.

**향후 개선 경로.** ① 역할-aware 재타이핑(안방/손님방, 부부/공용 화장실) 또는 객체·인접 맥락으로 역할 추론 → ② adj_L1을 **역할 수준으로 세분화** → ③ 문화권별 위상 규칙(SWRL 등)으로 평가·규제 확장. 그러면 더 엄격하고 문화가 반영된 충실도 측정이 가능. (현 한계를 디펜스에서 *명시적으로 선언*하는 것이 정직성·후속연구 동기 측면에서 유리.)

## 6. 후속 (재학습 시 §3 표에 행 추가, 최종값만)
- ✅ **v3 = +RPLAN 사전학습 / v4 = +결합(RPLAN+CubiCasa) 완료**(5시드). 결론: **사전학습 무익**(§4.3) — RPLAN조차 무사전학습보다 악화. 규모(≈27배)가 이득으로 이어지지 않음. *균형 한국 데이터 > 글로벌 사전학습.*
- ✅ **type조건(typed) 효과 측정 완료**(§7) — 최대 레버.
- 🔜 좌표 회귀(기하 도면)·graph-diffusion 차세대 생성기([[ROADMAP.md]], ADR-0001 plugin으로 추가).

## 7. type조건(typed) 효과 — 주거형태 조건화 [2026-06-05]

set-transformer + **house_type 임베딩**(조건 드롭아웃 0.3로 ANY도 학습) 생성기(ADR-0001 첫 plugin, `generators.typed`, arch=`set-transformer-typed`). 같은 체크포인트·시드(rng)로 **조건 ON(정답유형 주입) vs OFF(ANY)** 만 바꿔 균형 dwelling test 평가 → 순수 조건 효과. v0 × 5시드. 측정 `scripts/typed_effect.py`(소비자 `generators.load` arch-dispatch 검증 겸).

## 8. 데이터셋 조합 매트릭스 (v1~v7, combine) — 합쳐서 한 번 학습 [2026-06-06]

> **현재 단계 = 데이터셋 조합 실험**(전이학습 아님). 여러 데이터셋을 *합쳐 한 데이터셋으로 한 번에 학습*(`train_combine.py`)해 **어떤 조합이 최고인지** 비교. 각 5시드, 동결 균형 AI-Hub test(전 버전 공유). 정본=`runs/index.jsonl`(시드 정규화 `scripts/normalize_ledger.py` 적용), 조회 `scripts/show_combine_results.py`.

**버전 정의:** v0=AI-Hub 7,101(dual 클린·기준) · v1=AI-Hub 20,828 · v2=+CubiCasa 3,028 · v3=+RPLAN 80,371 · v4=+둘다 · v5=RPLAN만 · v6=CubiCasa만 · v7=RPLAN+CubiCasa(v5~7=글로벌만).

| 버전 | 데이터 조합 | 매크로↓ | 마이크로↓ | unseen↓ | 법규(off→on) |
|---|---|---|---|---|---|
| **v0** | AI-Hub 7,101 (클린) | 0.188 | **0.088** | **0.173** | 89→100% |
| v1 | AI-Hub 20,828 | 0.186 | 0.112 | 0.215 | 60→100% |
| v2 | + CubiCasa | 0.201 | 0.118 | 0.214 | 42→100% |
| v3 | + RPLAN | 0.189 | 0.112 | 0.216 | 0→100% |
| v4 | + CubiCasa + RPLAN | 0.190 | 0.116 | 0.203 | 0→100% |
| v5 | RPLAN만 (글로벌) | 0.496 | 0.494 | 0.502 | 0→100% |
| v6 | CubiCasa만 (글로벌) | 0.760 | 0.697 | 0.718 | 0→100% |
| v7 | RPLAN+CubiCasa (글로벌) | 0.505 | 0.480 | 0.477 | 0→100% |

**결론:**
1. **클린 AI-Hub(v0)만으로 최선.** 마이크로 0.088이 전 조합 압도(나머지 ≥0.112). 매크로는 v0≈v1(0.188/0.186, 노이즈 내 동률)이나 마이크로·unseen에서 v0 우위.
2. **AI-Hub 양을 늘려도(v1=20,828, V2V 확장) 개선 없음** — 매크로 동률, 마이크로·unseen 악화(V2V 노이즈). *수량≠품질* 재확인.
3. **글로벌을 합쳐도(v2·v3·v4) 무익** — 매크로 0.19대, 마이크로 0.11~0.12로 v0(0.088)보다 나쁨. 조합이 도움 안 됨.
4. **글로벌만(v5·v6·v7)은 국내 test서 처참**(매크로 0.50~0.76) → **글로벌↔국내 도메인 격차**. 한국 데이터 없이는 한국 도면 불가 = **소버린 데이터의 필요성을 데이터가 증명**. (방분포 §대시보드: RPLAN/CubiCasa엔 발코니·실외기실·현관이 빈약 — 한국 고유 패턴 결여가 원인.)
5. **규제루프(Symbolic) 가치 재확인** — 글로벌/RPLAN을 섞으면 사전(off) 법규가 0%로 폭락(글로벌 데이터는 한국 채광법 패턴 결여)하나, 규제루프 on이 전부 100%로 복구.

**패러다임 종합(조합 vs 전이학습):** 글로벌 증강은 **합치기(조합, §8)로도, 사전학습→파인튜닝(전이, §6)으로도 (한국 타깃 기준) 무익**. 둘 다 클린 AI-Hub만 못함. → 계획서의 "글로벌 사전학습 유익" 가정은 **(한국 동결 test에서) 반증**. **균형 잡힌 클린 한국(소버린) 데이터가 핵심.**

> ⚠️ **평가 편향 주의(중요).** test가 AI-Hub(한국)뿐이라 글로벌이 불리한 건 *부분적으로 설계상 당연*하다(소버린 목표엔 타당). 비자명한 발견은 *글로벌-only 실패*(예상된 OOD)가 아니라 **글로벌+한국 ≤ 한국 단독**(추가가 무해하지 않고 오히려 약간 해로움)이다. 따라서 결론은 **"한국 타깃·고자원(한국 7천~2만) 한정"** — 글로벌 데이터의 보편적 무용을 뜻하지 않는다. (ⓐ 글로벌·교차도메인 test, ⓑ 저자원 한국 상황에선 글로벌 사전학습이 유효할 여지.) + §5-1 역할·문화 한계(adj_L1이 역할 오류엔 관대).

## 9. 모델 용량 ablation (v0cap2x) — 파라미터를 키우면? [2026-06-06]

> epochs뿐 아니라 **모델 파라미터(용량)**도 성능에 영향. 기본값은 전 버전(v0~v7) 통일했고, 별도로 **같은 v0 데이터(AI-Hub 클린)에 모델만 2배** 키워 비교. `scripts/run_capacity.py`, 5시드.

| 모델 | embedding·layers·heads·FFN | APT | DEH | ROW | 매크로↓ | 마이크로↓ | unseen↓ |
|---|---|---|---|---|---|---|---|
| v0 (기본) | 48·2·4·96 | 0.137 | 0.195 | 0.233 | 0.188 | 0.088 | 0.173 |
| **v0cap2x (2배)** | 96·4·8·192 | 0.124 | 0.183 | **0.191** | **0.166** | 0.084 | 0.176 |

**결론:** **모델 용량을 키우면 개선됨**(매크로 0.188→0.166). 특히 **소수형태 ROW(연립)에서 −0.042로 최대**, DEH·APT도 소폭↓. unseen은 ≈동일. → *기본(작은) 모델은 소수 주거형태를 담기엔 용량 부족*이었고, 키우니 균형 성능이 올랐다. **데이터 조합(§8)·type조건(§7)에 더해 모델 용량도 소수형태 개선의 레버.** (예비 가설 "소량 데이터라 용량 무익"은 **반증** — macro/소수형태에서 분명한 이득.) 단 §5-1 한계는 동일 적용.

# KorPlan-Diff (코너-그래프 확산) — RPLAN 실험 결과 [2026-06-16]

> **엔진 = KorPlan-Diff** (코너-그래프 diffusion + 정렬손실; GSDiff 정렬 *사양*만 clean-room 재구현, 코드 차용 0/GPL-0, 소버린). RPLAN(중국) **사전학습** 단계 기록. 한국 파인튜닝(KorPlan-Diff-K)·KorPlan-AR(wall-cycle)은 별도. 작명=`korplan-model-naming`.

## 1. 셋업 (논문 인용용)
- **데이터**: RPLAN (USTC+Kujiale, 중국 주거 평면도). train+valid `.mat`에서 30,000 평면. **코너수 중앙값 22** (범위 8~51).
- **아키텍처(작은 모델)**: CornerDenoiser = transformer ε-denoiser (d=256, L=6, H=8) + 전역 코너수 임베딩. EdgeModel = transformer (d=160, L=5, H=4). 둘 다 수백만 파라미터 급(SOTA 대비 작음).
- **학습**: 코너 DDPM **50k step** (cosine schedule T=200, 정렬손실 align×20, 개수 조건부) + edge **25k step**. batch 128 (2-GPU DataParallel). AdamW lr 3e-4.
- **개수 조건부**: 샘플 코너수를 GT 실분포에서 추출 + 전역 count 임베딩(과소생성 방지). 정렬손실 = 각 코너 최근접 x|y 거리 배리어(GSDiff §1-B 재구현, `align_proto.py`).
- **재구성**: 생성코너 → axis공유 벽후보 → 평면화(교차제거) → **기하 각도 면순회**(`extract_rooms`) → 방 폴리곤. 구현 `scripts/corner_edge_engine.py`.

## 2. 평가지표 — ★중요 교정 (방법론)
- **`overlap_frac` 정의 교정**: 기존 *방 bbox 교차* → **실폴리곤 교차(shapely)** (`diag_placement.metrics`). bbox 겹침은 L자 방에서 *인공* 겹침을 만들어 완벽타일링도 0.2~0.27로 표시 → 과장.
  - 검증: 우리 재구성(평면 분할)의 실폴리곤 겹침 = **0.0000** (med·p90·max 전부). bbox지표 0.27은 **전부 L자 인공물**.
  - ⚠️ **공개 수치(GSDiff 0.074·DiffPlanner 0.229·wall-cycle 0.47)는 bbox overlap** → 실폴리곤과 *직접비교 불가*. 공정 비교는 동일 실겹침 기준이어야 함.
- **clean** = selfint_rooms=0 ∧ 실overlap<0.25 ∧ span_ratio<8.

## 3. 오라클 ablation (병목 격리) — 코너 생성 vs 재구성
| 수준 | 입력 | 방수 | 실overlap | 재구성 |
|---|---|---|---|---|
| L1 | GT코너 + GT벽 (재구성 상한) | ~4.0* | 0.0 | 64/64 |
| L2 | GT코너 + edge모델 예측벽 | ~4.7* | 0.0 | 64/64 |
| **L3** | **생성코너 + 재구성(실제 엔진)** | **7.9** | **0.0** | **63/64** |

\* L1/L2 방수는 기하 면순회가 *정확정렬(GT)*에서 collinear 각도타이로 과소(진단 한계, L3와 무관 — L3는 0.76px 오프라 타이 적음).

## 4. 근본원인 발견 (측정으로 확정, 추측 아님)
1. **edge 모델이 *생성* 코너에 OOD** — axis쌍 중 P>0.5: 생성 **21%** vs GT **58%** → 벽 **8 vs 27** → 격자 불완전. **단순 지터 아님**(GT+0.8px 지터엔 edge 정상: 벽28·방6).
2. **생성 코너는 기하적으로 타일링 가능** — axis+짧은벽+평면 휴리스틱으로 **100% 방형성**. 즉 코너 정상, *재구성*이 병목.
3. **자기교차 2원인 수정**: ① `extract_rooms`가 nx *임의* 평면임베딩 → **기하 각도 half-edge 면순회**로 교체(selfint 53→6) ② wall-cycle 코덱 grid스냅이 직교 방을 과양자화→교차 재유발 → 제거.
4. **★overlap 지표 교정** (§2) — 진짜 겹침은 0(완벽 타일링).
5. **junction 손실(격자 완전성)** — 모든 floor-plan 코너 = 격자 교점(x선 ∧ y선 공유). 정렬손실은 min(x,y)만 강제→dangling. junction은 max(x,y) 패널티 → 둘 다 공유 강제 → 완전 그리드(면없음↓). 구현 `align_proto.junction_loss`.

## 5. 결과 (RPLAN, **교정 실폴리곤 지표**)
| 모델 | 방수 | 실overlap | clean | 재구성 |
|---|---|---|---|---|
| GT (참조) | ~7.2 | 0.0 | — | — |
| **KorPlan-Diff-R** (사전학습) | **7.9** | **0.0** | **73%** | 63/64 |
| KorPlan-Diff-R + junction(w=10) | 10.5 | 0.0 | 85% | 63/64 |

**핵심**: KorPlan-Diff-R는 RPLAN에서 **실겹침 0의 완벽 타일링** 벡터 도면을 생성(clean 73%, 방수 7.9≈GT 7.2) — 정렬손실 재구현이 작동함을 입증. junction 손실은 완전성↑(clean 85%)이나 **과분할**(방수 10.5>GT 7.2) → w 3~5로 튜닝 필요.

## 6. 한계 · 다음
- L1/L2 오라클 방수 과소 = 기하 면순회의 정확정렬 collinear 타이(진단 한계, 후속 타이브레이크).
- ortho=0 (코너 0.76px 오프, `--snap` 옵션으로 복원하나 방수 trade-off; 실겹침 0이라 타일링은 깨끗).
- 모델 작음 — GSDiff 미달분(실겹침 동일 0이면 차이는 방모양·완성도)은 *구조 생성*(per-corner 의미) 미구현 탓. 학습량보다 구조 레버.
- **다음**: 한국 파인튜닝(KorPlan-Diff-K, RPLAN→한국 전이 검증) · KorPlan-AR(wall-cycle, 겹침 구조적 0) A/B.

## 7. KorPlan-Diff-K — 한국 전이 예비 결과 [2026-06-16]
RPLAN 체크포인트(`korplan_diff_r`)에서 **한국(AI-Hub corrected geomgraph) 파인튜닝** 15k step, junction-w 4.
- **★전이 성공**: 한국 코너 L3 = **재구성 64/64(면없음 0) · 실겹침 0.0(완벽 타일링) · clean 71%**. → *소버린 한국 벡터 도면 생성*(Phase 1 핵심 가설) 실측 성립. 메모리 1순위 디리스크 항목 ✓.
- **caveat 1 — 데이터 커버리지**: 한국 APT 평면이 RPLAN보다 훨씬 복잡. **코너수 대부분 >53(N_MAX)** → 39,117개 중 **835개(2%)만 로드**(가장 단순한 것). RPLAN 코너 중앙값 22 vs 한국 >53. **N_MAX 상향(예: 120) + 전체 한국 재파인튜닝 필요.** ※ 이 복잡도 격차 자체가 전이 난이도의 정량 근거(논문 소재, [[rplan-vs-korean-node-granularity]]).
- **caveat 2 — 과분할**: 방수 18.8 > 한국 GT ~13. junction-w 4가 한국 세밀구조엔 강함 + 재구성 과생성 → w 튜닝(1~3) 필요.
- 결론: 전이는 *기계적으로 작동*(깨끗 타일링), 정밀화(N_MAX·junction-w·전체데이터)가 1편 본 결과 전 과제.

# KorPlan-AR (wall-cycle 자기회귀) — RPLAN 실험 결과 [2026-06-18]

> **엔진 = KorPlan-AR** (wall-cycle + opening 토큰을 transformer로 자기회귀 생성; ADR-0012 생성타깃·`wallcycle_codec.py`). KorPlan-Diff와 *동일 코퍼스(RPLAN)·다른 표현*. 작명=`korplan-model-naming`. ckpt `korplan_ar_r.pt`.

## 1. 셋업 (논문 인용용)
- **데이터**: RPLAN 토큰화셋 `data/staging/tokens_rplan` — train **72,555 plans**, 평균 n_tokens ~160, n_rooms 6~9. 토큰 = wall-cycle 코덱(방 cycle + 코너 grid좌표 + role + opening).
- **아키텍처**: decoder-only transformer (d_model=256, n_layer=6, n_head=8, max_len=1152). `scripts/train_wall_cycle.py`.
- **학습**: 200 epoch, batch 32, AdamW lr 3e-4, **`--constrained`**(유효성 마스크 디코딩) **`--orthogonal`**(직각 강제). RPLAN ckpt에서 연장(`--init`).
- **샘플링**: top_k=40, temp 1.0, constrained mask. 렌더 `render_samples.py` → decode → `cadrender.from_geomgraph`+autocorrect → PNG.

## 2. 결과 — 최종 ep200 (수렴)
| epoch | loss | valid | uniq | rooms~ |
|---|---|---|---|---|
| ep150 | 0.4151 | 1.0 | 1.0 | 7.1 |
| **ep200 (최종)** | **0.4125** | **1.0** | **1.0** | **6.9** (max9) |

- **valid 1.0 · uniq 1.0** = 생성 토큰열이 항상 디코딩 가능한 *닫힌* 도면 + 배치 내 중복 0. wall-cycle의 구조적 강점(겹침·미완결 구성상 차단).
- ep150→200 거의 수렴(loss 미세, 방수 안정) — 추가 학습 이득 미미.
- **렌더 정성평가**(ep200, n=12 CPU): 방 6~9개. **~8/12 깨끗한 직사각형 아파트형 타일링**(빈틈·겹침 0). **~4/12 대각선/붕괴 아티팩트**(`--orthogonal`인데도 잔존) → 직각강제·재구성 보강 과제.

## 3. ★개구부(문/창) 부재 = RPLAN 데이터 한계 (모델·렌더 버그 아님)
생성물 전 샘플 **doors=0 / windows=0**. 근본원인을 토큰 카운트로 확정(특수 id `OPEN=5·DOOR=6·WINDOW=7`, `wallcycle_codec.py`):

| 코퍼스 (train.jsonl) | plans | DOOR(6) | WINDOW(7) | OPEN(5) |
|---|---|---|---|---|
| **RPLAN** (`tokens_rplan`) | 72,555 | **0% (0개)** | **0% (0개)** | 100% (6.78/plan) |
| **한국** (`tokens_parsed_apt`) | 26,646 | **95% (~9.4/plan)** | **95% (~10.8/plan)** | 100% |

- **RPLAN은 방-방 경계를 전부 `open`(벽없는 공유)으로만 인코딩** — 문/창 토큰이 데이터에 단 하나도 없음. ∴ AR이 문/창을 안 내는 건 **데이터를 정직하게 학습한 결과**(생성·렌더 결함 아님).
- **한국 데이터엔 문 95%·창 95%로 풍부** → 개구부는 **RPLAN→한국 파인튜닝 단계의 자원**. RPLAN으론 구조적으로 불가능. ⇒ "RPLAN 완벽" freeze 판정은 *배치 품질(대각선 아티팩트)* 만 보고 내리고, 문/창은 한국 몫(로드맵 정합). [[rplan-no-doors-windows-korean-has]]

## 4. 대각선 아티팩트 — 조사 → 직각화 알고리즘 [2026-06-18]

생성물의 잔여 사선(`--orthogonal` 디코드 마스크가 못 막는 폴백 누수)을 **조사부터** 했다(`survey_shapes.py`, 160도면·1,069방, 공선점 제거 후 코너수 nc·대각선 변 n_diag).

**모양 분류(조사 결과):**
| nc(코너) | 방수 | 직각/대각 | 의미 |
|---|---|---|---|
| 4 | 843 | 840/3 | 직사각형(다수) |
| 6 | 60 | 52/8 | L자=복도귀퉁이 거실(정상) |
| 8·10·12 | 119 | 95/24 | 복잡 요철(정상) |
| 3·5·7·9·11(홀수) | 24 | **0/24** | 전부 대각(아티팩트) |

- **★가설 확증**: 직각 폴리곤은 코너가 항상 *짝수* → **홀수 코너 ⟺ 대각선(100%, 24/24)**. 짝수 코너 = 97% 직각.
- **★핵심 발견**: 대각선 변은 **항상 정확히 1개**(n_diag ∈ {0,1}, 분포 1010:59). = 닫는 변이 축정렬 안 된 것.
- 전체 직각방 **94.5%**, 대각 5.5%. 기준은 *코너수 아니라 n_diag*(6코너 L자는 정상 보존, 5코너는 거절).

**알고리즘 = L-코너 삽입 수리(`wallcycle_codec.rectify_diagonals`)**: 대각선 a→b를 점 (b.x,a.y)|(a.x,b.y) 삽입으로 H+V 두 직각변 분해(자기교차 안 생기는 쪽). 변을 *옮기지 않고 꺾어* 면적 보존. 삼각형도 4코너로 펴짐. `_rectilinear_poly`(그리디 스냅, 삼각형 못 펴짐)의 정확한 교체.
- **결과: 직각방 94.5% → 99.4%**(survey --rectify). 잔여 0.6%(병리적 슬리버)는 clean 필터의 `n_diag==0` 거절로 제거.
- **★숨은 버그 — 대각선 *벽 세그먼트*** (`debug_diagonal.py`로 격리): 방 폴리곤은 100% 직각(필터 전후·렌더 후 대각 0)인데 렌더엔 사선 잔존 → `cadrender`가 그리는 `g["walls"]` 중 ~6%가 대각선 세그먼트(codec이 어긋난 코너쌍을 이은 잉여 벽). 필터가 *방만* 검사하고 벽을 안 본 게 구멍. **수정 = 렌더 직전 대각선 벽 드롭**(방 경계=진짜 벽, 잉여만 제거, 거절 0). → **출력 100% 직각**(`ar_ep200_v2.png`).
- **외곽(footprint) 품질** — 진짜 RPLAN(500) vs 생성(200) 비교(`survey_outline.py`): 중앙값 채움비 비슷(0.80 vs 0.78)이나 **생성은 꼬리 불량 — 분리(연결 끊김) 21.5% vs 진짜 1.0%**, fill p10 0.45 vs 0.68. 대응 = footprint 거절(연결1·fill≥0.6·convex≥0.75, 진짜 분포 기준).
- ★중요: 사선·벽·외곽 해결 후 clean율(배치 기준) ~46%의 **거절 사유가 기하 아티팩트→배치(겹침·분리·세장)로 이동**. 즉 RPLAN 품질 병목이 "기하 아티팩트"에서 "방 배치 품질"로 분리 확정 — 후처리 아닌 **모델/한국데이터 레버**.

## 4-B. 연장 학습 ep200 → ep580 = plateau 확증 (freeze 근거) [2026-06-18]

ep200 가중치에서 옵티마이저 복원(seamless)으로 연장 학습. **동일 파이프라인**(`render_geomclean.py --constrained --orthogonal`, country=0)으로 두 ckpt를 CPU 렌더 비교 — 학습은 GPU1에서 계속(2-GPU 동시 풀로드 트립 회피 위해 렌더는 CPU, `no-concurrent-heavy-render-during-training`).

| ckpt | train loss | clean율 (N=100 고정·조기종료無) |
|---|---|---|
| **ep200** | 0.4125 | **48% (48/100)** |
| **ep580** | 0.3975 (ep575) | **52% (52/100)** |

- **★plateau 확증**: loss(0.4125→0.3975, ≈0.01)·clean율(48%→52%, **4pp**) **둘 다 미동**. clean율 4pp 차이는 이항 표준오차(±5pp, N=100) 이내 = **통계적으로 동등**. ep200 이후 ~380 epoch 추가 학습의 배치품질 이득 ≈ 0.
- **주의(측정 함정)**: 1차 측정은 `--render 12` 조기종료라 n_total이 censored(ep200 12/39=31%, ep580 12/24=50%)로 **차이 과장**. 고정 N=100 무편향 재측정에서 48% vs 52%로 수렴 — 작은 표본·조기종료의 분산 아티팩트였음. *clean율은 항상 고정 N으로 측정할 것.*
- 몽타주: `docs/runs/cmp_ar_ep200.png` · `cmp_ar_ep580.png`(각 clean 12장). 정성도 거의 구분 불가.
- **함의**: RPLAN AR은 ep200에서 이미 수렴 → **freeze 근거**(최종 판정=사용자 렌더 검수, 클로드 선언 금지 `handoff-v3-rectilinear-train`). 배치품질 천장(clean ~50%)은 *학습량* 레버가 아닌 **모델/표현/한국데이터** 레버로만 넘을 수 있음을 재확인. ckpt 백업 `korplan_ar_r_ep200.pt`·`korplan_ar_r_ep580.pt`.

## 4-C. ★중대 정정 — plateau는 "방법 천장"이 아니라 "용량 한계" (FMLM 대조, 2026-06-19)
앞선 "clean ~50% plateau = 방법 천장" 진단은 **틀렸다.** AR과 **동일 패러다임**인 FMLM(CVPR'26, arxiv 2604.04859, 자기회귀 토큰+constrained decoding)을 논문에서 정밀 분석한 결과(`docs/LITERATURE.md §FMLM 정밀기록`):
- **batch·학습량은 범인 아님**: FMLM도 **batch 32(동일)**, epoch 50(우리는 200~580로 *더 많이* 학습), 데이터 RPLAN(동일).
- **진짜 갭 = 모델 용량 + 누락된 ablation 요소**:
  - 용량: FMLM **80M**(24L/512d/32h) vs 우리 **5.1M**(6L/256d/8h) = **16× 작음**.
  - FMLM ablation이 입증한 필수요소 중 우리가 안 했을 가능성: **방 index 내림차순**(빼면 FID 25.5→94.6 붕괴, Table 7) · **room permutation 증강**(Table 6) · **LLaMA-3 블록**(RoPE/SwiGLU/RMSNorm).
- ∴ **5.1M 모델 clean율 plateau로 "천장" 선언한 것은 표본 오독.** 다음 = 코드 대조(내림차순·permutation·아키텍처) → 갭 메우고 FMLM-스펙(80M)으로 재학습 → 용량 가설 실측. [[korplan-model-naming]]

## 5. 한계 · 다음

# KorPlan-AR 80M (FMLM 방법 재현) — SOTA급 baseline 증명 [2026-06-20] ★논문 자료

> **논문 주장 (정확히)**: KorPlan-AR은 SOTA인 **FMLM**(Unified Vector Floorplan, CVPR'26)의 *엔진을 가져온 게 아니라 **방법을 from-scratch 재현***한 것이며, RPLAN에서 **SOTA급으로 작동**함을 증명한다. 그 위에 **한국 데이터 + 규제-인식 생성 + 한국특성 조치**가 우리 기여다.
> ⚠️ **"FMLM을 이긴다"는 주장 아님.** FMLM이 도면 성능은 더 우수(permutation 증강·정확 프로토콜·A100). 우리는 *동급 재현 + 신규 기여*를 주장한다.

## 1. 방법 충실도 — 코드 레벨 ("가져온 게 아니라 따라 했다"의 직접 증거)

## 4. 측정 선택 — FID 미사용 이유 (방어 논리)
- FMLM은 FID/GED/IoU, 우리는 **기하 검증(clean·겹침·footprint)** — 본 프로젝트 방침 "CAD 품질 > FID"(§5-A) 정합.
- cross-paper FID는 **프로토콜(렌더·레퍼런스·eval코드) 비동일**이라 7.22와 직접비교 불가 + permutation 갭으로 불리 → SOTA급 주장은 **방법-충실도(§1) + 기능검증(§2)**로 한다. (FID 하네스 `scripts/fid_rplan.py`는 내부 sanity check용으로만 보유.)

## 5. ★footprint 지표 미스매치 — 한국=벽두께 표현, 데이터 정상 (실측 정정) [2026-06-20]
> ⚠️ 앞서 "한국 데이터가 천장"이라 본 것은 **지표 오류였다.** 간격(벽두께) 허용을 늘리며 GT footprint를 재측정(n=300, shapely buffer-union 연결성분):
| gap 허용(span 대비) | 한국 GT 단일% | RPLAN GT |
|---|---|---|
| 0% (strict, 변 맞닿음) | **0%** (med 12조각) | 100% |
| 1% | 47% | 100% |
| **2%** | **99%** | 100% |
- ★**한국 GT는 ~2% 간격만 허용하면 99%가 단일 건물.** = 방을 **벽두께만큼 띄워** 그리는 *현실적 표현*이지 파편화 아님. RPLAN은 변-맞닿음(벽두께 0)이라 strict서 100%.
- ∴ **strict footprint-단일 지표는 RPLAN식(변 맞닿음) 가정 → 한국(벽두께 표현)엔 부적합.** "한국 footprint 0%"는 품질 실패가 아니라 **지표 미스매치.** **한국 데이터·엔진 둘 다 정상.**
- 함의: **연결성은 한국 병목이 아니다.** 벽두께-인식 지표(간격 tol)로 평가해야 공정 — Python만으로 즉시 정정(재학습 0).

## 7. 현재버전 Python 개선 (재학습 0) — ★수리 실패, rejection이 답 [2026-06-20]
