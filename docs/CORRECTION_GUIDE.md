# 사람을 위한 보정 가이드

> **대상:** AI-Hub 도면을 `fix`(보정 대기)에서 `use`(데이터셋 채택)로 살리는 작업을 하는 사람.
> **핵심:** 모델(YOLO)을 안 건드려도, 사람이 **규칙·임계·기준·검수**를 손보면 `use`가 는다. 단 *틀린 그래프를 늘리는 것*과 *맞는 그래프를 더 잘 살리는 것*을 항상 구분하라.
> 관련: [V2V.md](V2V.md)(모델·실험 원장) · [DATA.md](DATA.md)(처분 회계·불변식) · [ARCHITECTURE.md](ARCHITECTURE.md)(검출 기술)
> 검수 콘솔: https://plan2graph.aines.kr

---

## 0. 제1원칙

1. **원본을 먼저 본다.** 해석(그래프)을 단독으로 믿지 말고, 항상 원본 PNG와 나란히 대조한다(콘솔 `나란히` 모드).
2. **평가지표는 `use` 숫자만이 아니다.** 규칙·임계를 바꿀 때는 **fix→use 증가 + 오채택률(틀린 그래프가 통과한 비율) 표본검수**를 함께 본다. mAP·use만 보면 품질이 무너진다.
3. **정밀화 vs 완화를 구분한다.**
   - **정밀화**(있는 정보를 더 잘 읽기/기준을 더 정확히) → 순이득, 적극 권장.
   - **완화**(유효 기준을 느슨하게) → 품질↔수량 트레이드오프, **데이터셋 버전을 올리고 의식적으로만**.
4. **test 셋은 불변.** 규칙·임계 변경은 train/val에만 반영. 변경 시 데이터셋 버전을 올린다(v2→v2.1).

## 2. 게이트 격리 사유 → 원인 → 사람의 조치 (치트시트)

도면이 `use`가 못 되고 격리되면 사유가 찍힌다(`quarantine.csv`). 사유별 대응:

| 격리 사유 | 뜻 | 1차 의심 | 사람의 조치 |
|---|---|---|---|
| `no_unit_with_entrance` | 현관 가진 세대를 못 찾음 | 현관문 검출/연결 실패 | ② 문매칭 정교화 · ③ `DOOR_MAX_GAP_PX`↑ · ⑤ 원본에 현관문 직접 라벨 |
| `missing_essential:현관/거실/…` | 필수 5요소 중 누락 | 라벨 누락 or 주거유형 특수(원룸) | ④ 주거유형별 필수요소 재정의 · ⑤ 원본 확인 후 라벨 보완 |
| `R5_unresolved_doors` (integrity_failed) | 못 푼 문이 있음 | 문-벽 좌표 어긋남 | ③ `DOOR_MAX_GAP_PX`↑ · ② probe 개선 |
| `R2_doorless_room` | 문 없는 방 존재 | 문 누락 or 개방통로 미인식 | ② 개방통로 판정 보강 · ③ `OPEN_MIN_RATIO`↓ |
| `R1_isolated_component` | 고립된 공간 덩어리 | 통로 미연결 | ② 인접/개방 통로 규칙 · ⑤ 검수 |
| `R3_unreachable_from_entrance` | 현관에서 도달 불가 | 중간 통로 끊김 | ② 통로 규칙 · ⑤ 검수 |
| `too_few_rooms:n` / `too_many_rooms:n` | 방수 범위 밖(5~60) | 분할 실패 or 다세대 잔류 | ④ `ACCEPT_MIN/MAX_ROOMS` 재검토 · ⑤ 검수 |

## 3. 층별 작업법

### ② 기하 규칙 (`topology.py`) — 1순위, 순이득
모델이 문을 **검출은 했는데 두 방을 잇는 엣지로 못 만든** 경우가 격리의 큰 비중이다. 같은 예측으로도 더 살릴 수 있다.
- 문↔벽 법선 probe 거리·각도 허용범위
- 창(window)을 **발코니 통로**(via=balcony)로 승격하는 조건
- 벽 미피복 트임을 **개방통로**(via=open)로 인식하는 판정
- **리스크 낮음**(틀린 정보를 만드는 게 아니라 있는 정보를 더 잘 읽음). 코드리뷰 + 표본검수로 충분.

### ③ 임계 파라미터 (`config.py`) — 빠름(재빌드만)
`P2G_` 접두어 환경변수로 **코드수정·커밋 없이** 변경 후 재빌드:
```bash
export P2G_OPEN_MIN_RATIO=0.40      # 개방통로 판정 완화/강화
export P2G_OPEN_MAX_GAP_PX=80       # 개방통로 최대 간격(px)
# 재빌드: build_dataset.py --predicted ... 로 재변환
```
env로 조정 가능: `OPEN_MIN_RATIO`(0.30) · `OPEN_MAX_GAP_PX`(60) · `MIN_ETC_AREA_PX`(10000) · 법규값(`LEGAL_BEDROOM_MIN_M2` 등).
**코드 수정 필요**(상수): `DOOR_MAX_GAP_PX`(60) · `MAX_UNRESOLVED_RATIO`(0.20) · `ACCEPT_MIN_ROOMS`(5) · `ACCEPT_MAX_ROOMS`(60).
> ⚠️ 임계를 풀면 use는 늘지만 **틀린 그래프도 통과**한다. 변경 전후로 새로 통과한 표본을 반드시 눈으로 검수(오채택률 측정).

### ④ 정책/기준 (`classify_unit`, `rules.py`) — 도메인 판단
"무엇이 유효한 평면도인가"의 정의. 사람만 할 수 있다.
- **필수 5요소**(`ESSENTIAL_ROOM_CLASSES`: 현관·거실·침실·주방·화장실)는 일반 아파트 기준. **원룸/스튜디오**는 현관·거실·주방이 한 공간이라 전부 격리됨 → "주거유형별 필수요소"를 정의하면 *정당하게* use↑(완화 아님, **정밀화**).
- R1~R5(`rules.py`)는 위상 신뢰도의 핵심. **R2(문 없는 방)·R4(현관 존재)를 끄는 건 금지** — 틀린 그래프가 섞인다.
- 기준 변경은 **데이터셋 버전 up + test 동결**.

### ⑤ 인간검수 (`admin.py` 콘솔) — 잔여·원본미완성 전용
모델 유니온·규칙으로도 안 풀리는 잔여(예: 두 STR 모델 다 실패한 392건, 원본에 문 정보가 아예 없는 593건). 콘솔에서:
- **3-모드 검수**: `나란히`(원본 | 해석 좌우) → `겹쳐보기` → `원본만`. **항상 원본 먼저.**
- **원본 ∥ 그래프 단건검수** + 정상/격리 **결정 버튼**으로 경계 케이스 수동 판정.
- 범례: 🔴문 · 🟢발코니(미닫이창) · 🟠개방통로 · 🟣인접병합 · ⚫현관↔외부.
- 원본에 **누락된 현관문을 직접 라벨링** → 영구 floor를 깸(최고 정확도).
- 반복 실패 패턴을 발견하면 ②③④로 환류(예: "이 유형 도면이 자꾸 R5로 떨어진다" → `DOOR_MAX_GAP_PX` 조정).

## 4. 변경 안전수칙 (필수)

규칙·임계·기준을 바꿀 때마다:
1. **전후 측정**: fix→use 증감 **그리고** 새로 통과한 표본의 **오채택률**(틀린 그래프 비율)을 표본검수.
2. **격리로의 회귀 확인**: 한쪽을 풀어 다른 쪽이 깨지지 않는지(EXP-1처럼 교체가 −122였던 사례).
3. **원장 기록**: [V2V.md](V2V.md)에 (변경내용, fix→use, 오채택률, 적용 split) 한 줄 추가.
4. **test 불변·버전 up**: train/val에만 적용, 데이터셋 버전 올림.

## 5. 역할별 체크리스트

- **규칙 작성자(②)**: `topology.py` 문/통로 휴리스틱 → 코드리뷰 + 표본검수 → 순이득 확인.
- **임계 튜너(③)**: `P2G_*` env 조정 → 재빌드 → fix→use **및** 오채택률 동시 확인.
- **정책 결정자(④)**: 주거유형별 필수요소·R1~R5 의미 정의 → "정밀화"인지 "완화"인지 명시 → 버전 분리.
- **검수자/라벨러(⑤)**: 콘솔에서 원본 먼저 → 잔여·원본미완성분 수동 복구·판정.
- **회계 감사자(전층)**: 모든 변경을 원장에 기록, test 불변 감시, "use만 늘고 품질 떨어지는" 변경 차단.
