# 사람을 위한 보정 가이드 (정보 보정 에디터)

> **대상:** R2G 파서가 뽑은 그래프(Parsed)를 사람이 보정해 **Corrected**로 만드는 사람.
> **어디서:** 정보 보정 에디터 → **[plan2graph.aines.kr/editor/](https://plan2graph.aines.kr/editor/)**
> **핵심:** 모델·코드를 안 건드려도, 에디터에서 **역할·연결·노드를 직접 고치면** 쓸 수 있는 도면이 는다.
> 단 *틀린 그래프를 만드는 것*과 *원본대로 바로잡는 것*을 항상 구분하라([[topology-is-grammar-not-picture]]).
> 관련: [ADR-0008/0009](adr/README.md)(Parsed/Corrected·그래프JSON 편집) · [ADR-0010](adr/0010-representation-g04-completion-layers.md)(g-0.4 표현) · [DATA.md](DATA.md)(처분 회계) · 게이트 판정 = `plan_quality.classify`(단일 소스).

---

## 0. 제1원칙

1. **원본을 먼저 본다.** 에디터는 원본 PNG를 불변 배경으로 깔아준다([[inspect-original-first]]). 추출 폴리곤(해석)만 믿지 말고 **항상 배경 도면과 대조**한다. 문·치수·여닫이는 배경 PNG에 이미 그려져 있다 — 다시 그리지 않는다.
2. **과보정 금지.** 위상은 *문법(제약)*이지 그림이 아니다([[topology-is-grammar-not-picture]]). 원본에 있는 연결·역할만 선언하고, **없는 벽·없는 문을 발명하지 않는다**(벽 없는 경계는 `open`).
3. **정밀화 ≠ 완화.** 원본대로 더 정확히 읽는 건 순이득(권장). "그냥 통과시키려고" 억지로 고치는 건 데이터 오염. 게이트는 통과 자체가 목적이 아니다.
4. **이미 있는 정보는 다시 입력하지 않는다.** 문 유무·종류 등 탐지된 값은 조인으로 도출된다([[derive-dont-duplicate-known-info]]). 사람은 **관계(연결)와 역할**만 선언한다.
5. **Parsed는 건드리지 않는다.** 보정본은 `edits/`에 따로 저장된다(원본 `graphs/`는 읽기전용). 비교축 = **Parsed ∥ Corrected**(= 사람 보정의 가치 측정, ADR-0008/0009).

## 1. 에디터 한 바퀴 (화면 구성)

| 영역 | 무엇 | 비고 |
|---|---|---|
| **plan_id 바** | 현재 도면 ID + 📋복사 | 파일명 접두(`APT_`)는 **원본 라벨일 뿐** |
| **🏠 거주형태** | APT/DEH/ROW 보정 드롭다운 | 파일명과 다르면 ⚠ 표시. 메타(`house_type`/`housing_type`/`house`)를 일관 보정 — **파일명은 안 바꿈** |
| **보정 완료 (전체 중)** | `edits/`에 저장된 수 / 전체 수 | **진행률**이지 현재 위치가 아니다 |
| **상태 pill** | ✅ 변환 통과(사용가능) / ❌ 보정 필요 + 사유 | `plan_quality.classify` 결과 |
| **편집 모드** | 🎨역할 · 🔗인접 · ⛓합치기 · 🗑삭제 · ✂나누기 | 아래 §3 |
| **도면 찾기** | ID 일부 검색 + 번호 목록(`1. 2. 3…`) + ◀이전/다음▶ | 목록은 앞 250개. 그 이후는 **검색**으로 |
| **저장 / ↶되돌리기** | `edits/`에 1회 저장 · Ctrl+Z | 저장 시 게이트 재판정 |

**단축키:** `R`역할 `A`인접 `M`합치기 `D`삭제 `S`나누기 · 역할 `1~9 0 a~f` · `E`현관 · `O`직각스냅 토글 · `F`맞춤 · `Ctrl+Z`되돌리기 · `Ctrl+S`저장. 휠=확대, 드래그=이동.

## 2. 게이트 "보정 필요" 사유 → 어느 모드로 고치나 (치트시트)

상태 pill이 ❌면 사유가 함께 찍힌다(`plan_quality.classify`, 한 도면이 여러 사유에 걸릴 수 있음). **반드시 원본과 대조 후** 고친다.

| 사유 | 뜻 | 1차 의심 | 사람의 조치(모드) |
|---|---|---|---|
| `현관없음` | 현관 역할 0개 | 추출 누락 / 전실을 현관으로 못 봄 | 🎨**역할**: 현관인 방 클릭 → `E`. ([[vestibule-vs-entrance-mislabel]] 주의) |
| `현관≠1(병합)` | 현관 2개+ | 다세대 병합 / 중복 검출 | 🗑**삭제**(중복 현관) · 또는 ✂**나누기**(세대 병합이면) |
| `거실≠1` | 거실 0 또는 2개+ | 오라벨 / 누락 / 병합 | 0개→🎨**역할** 거실 지정 · 2개+→⛓**합치기** 또는 🗑삭제 |
| `거실오라벨` | 거실이 최대 거주공간이 아님 | 더 큰 방이 거실인데 다른 역할 | 🎨**역할** 재지정(가장 큰 거주공간=거실) |
| `발코니과다` | 발코니 5개+ | 확장발코니 옛 벽선이 방으로 오검출 | 🗑**삭제**(헛 발코니) 또는 🎨역할 재지정 |
| `기타과다` | 기타(미상) 4개+ | fragment·노이즈 누적 | 🎨**역할**(기타→실제 역할) · ⛓**합치기**(쪼개진 한 방) · 🗑삭제(노이즈) |
| `침실<화장실` | 최소 침실 < 최대 물공간 | 면적/라벨 모순 | 🎨역할 재지정 또는 ⛓합치기/✂나누기(분할 오류) |
| `방없음` | rooms 비어있음 | 추출 전면 실패 | 에디터 보정 불가 → 원본 확인·제외 대상 |

> **연결공간 흡수**(별도 사유는 아니지만 흔한 품질 문제): R2G가 복도·파우더룸·전실을 옆 큰 방에 흡수해 거실/드레스룸이 길쭉해진 경우 → ✂**나누기**로 복원([[split-connecting-spaces]], [[canonical-kr-apartment-topology]]).

## 3. 5개 편집 모드 + 거주형태

전부 **방 폴리곤을 클릭**해서 동작한다. 큰 방이 아래, 작은 방이 위로 그려져 겹쳐도 작은 방이 클릭된다.

### 🎨 역할 (R) — 가장 많이 쓰는 모드

방 클릭 → 선택 → 역할 팔레트 클릭 또는 숫자/문자키. 선택 방에 `E` = 현관 지정.

- 오라벨·미상(기타) 역할을 원본대로 바로잡는다. **순이득**(있는 공간에 맞는 역할만 부여).

### 🔗 인접 (A) — 두 방의 연결 토글

방 **A** 클릭 → 방 **B** 클릭. 클릭할 때마다 **없음 → 문(door) → 개방(open) → 없음** 순환.

- 끊긴 통로를 잇거나, 문이 아니라 트인 연결이면 `open`으로. **원본에 실제로 연결이 있을 때만**(없는 연결 발명 금지).

### ⛓ 합치기 (M) — 과분할 노드를 하나로

합칠 노드들을 클릭(2개+, 첫 선택이 **기준**=역할/속성 유지) → `Enter` 또는 합치기 버튼.

- 한 공간이 벽선 두께로 여러 조각으로 쪼개진 경우. 폴리곤은 union, 엣지는 자동 재연결(서버 `_merge_nodes`).

### 🗑 삭제 (D) — 잘못된 노드 제거

삭제할 방 클릭 → 노드 + 연결 엣지 제거. 실수 시 `Ctrl+Z`.

- 헛 발코니, 노이즈 fragment, 중복 현관 등 **원본에 없는 방**만.

### ✂ 나누기 (S) — 흡수된 연결공간 복원

길쭉한 방(거실·드레스룸) 클릭 → 가로지르는 컷 **2점** 클릭 → 좌/우 역할 지정 → `Enter`.

- 컷 후 문·엣지는 기하로 자동 재분배(서버 `graph_edit.split_room`). `O`=직각 스냅(박스형) 토글, `Shift`=자유각.
- 한국 정준 위상(현관→복도→거실, 안방→전실→드레스룸)의 **연결공간(복도/파우더룸)** 을 되살릴 때 핵심.

### 🏠 거주형태 — 메타 보정 (신규)
파일명 접두(`APT_`)는 원본 라벨일 뿐 실물과 다를 수 있다(예: 이름은 APT인데 실제 **연립=ROW**). 드롭다운에서 APT/DEH/ROW로 고치면 `g.house`·`meta.house_type`·`meta.housing_type`(ADR-0013 도메인 조건메타)가 **일관 보정**된다. **파일명/ID는 바꾸지 않는다**(전 파이프라인의 키라 rename하면 참조가 깨짐). 접두와 다르게 고치면 ⚠로 계속 표시된다.

## 4. 저장 · 비교 · 안전수칙

1. **저장 = `edits/`에 1회.** 원본 `graphs/`는 불변. 저장하면 상태 pill이 게이트 재판정으로 갱신된다.
2. **통과(✅)가 목적이 아니다.** 원본과 맞는 보정이 목적. 억지 통과(없는 방 삭제로 게이트만 맞추기 등)는 데이터 오염 → 금지.
3. **비교축은 Parsed ∥ Corrected.** 사람 보정의 가치는 "보정 전후 같은 엔진에서 도면 품질 차이"로 측정된다([[goal-is-comparable-program-not-results]]). 보정으로 **사용 데이터를 늘리고**, 재학습 여부는 사용자(연구자)가 판단.
4. **회계.** 처분(사용/보정필요/제외)·숫자는 [DATA.md](DATA.md)/[[dataset-disposition-accounting]] 회계가 정본 — 새 버킷·숫자 신설 금지.

## 5. 이건 에디터가 아니라 "코드(개발)" 영역

아래는 사람이 에디터로 고치는 게 아니라, R2G 파서(Parsed 자동 품질)를 개발자가 손보는 별도 트랙이다(혼동 금지):
- 문↔벽 매칭·개방통로·발코니 판정 = `topology.py`
- 게이트 임계 = `plan_quality.py`(`MAX_BALCONY=4`·`MAX_ETC=3`) · `config.py`(`P2G_*`)
- 검출 모델(V2V/YOLO) = [V2V.md](V2V.md)
> 에디터에서 **같은 유형이 반복해서 보정 필요로 떨어지면** 그 패턴을 개발 트랙으로 환류한다(예: "전실을 자꾸 현관으로 못 본다" → 파서/온톨로지 보강).
