# 건축 도면 위상 데이터셋 구축 — Claude Code 작업 명세서

> 이 문서는 Claude Code가 읽고 자율적으로 구현하기 위한 작업 지시서입니다.
> 목표는 **AI-Hub 건축 도면 데이터(이미지+COCO 라벨)를 "방-문-방 위상 그래프" 데이터셋으로 변환**하는 것입니다.
> 이 데이터셋은 후속 단계(Neuro-Symbolic 도면 생성·검증 모델 학습)의 입력이 됩니다.

---

## 0. 작업 원칙 (중요 — 먼저 읽을 것)

1. **추측 금지·실데이터 우선.** 아래 데이터 스펙은 AI-Hub 공식 설명서 기준이다. 그러나 `attributes` 필드 세부, 좌표 단위, 폴리곤 방향 등은 **실제 JSON 1개를 먼저 파싱해 검증**한 뒤 확정하라. 가정과 실제가 다르면 가정을 고치고 그 사실을 `NOTES.md`에 기록하라.
2. **평면도(FP) 우선.** 위상 그래프는 평면도에서만 의미가 있다. 단면도(CS)·입면도(EP)·구조도(SD)는 1차 범위에서 제외하고, 평면도 41,556장에 집중하라.
3. **점진적 검증.** 전체 48,033장을 처음부터 돌리지 마라. (a) 1장 → (b) 손으로 검증할 수 있는 10장 → (c) 100장 → (d) 전체 순으로 확장하라. 각 단계에서 실패율을 측정·기록하라.
4. **최대 난관을 알고 시작하라.** 이 프로젝트의 핵심 리스크는 **"문이 어느 두 방을 연결하는가"가 라벨에 없다**는 점이다(아래 Task 1-3 참조). 여기 정확도가 전체 데이터셋 품질을 좌우한다. 여기에 가장 공을 들여라.
5. **결정은 코드가 아니라 사람에게.** 라이선스 판단, 규칙(법규) 해석 등 도메인 판단이 필요한 지점은 임의로 정하지 말고 `DECISIONS_NEEDED.md`에 질문으로 남겨라.

## 1. 프로젝트 목표와 성공 기준

### 최종 산출물
평면도 PNG + COCO JSON 한 쌍이 들어오면, 다음을 출력하는 재현 가능한 파이프라인:
- **위상 그래프**: 노드=공간(방), 엣지=문 연결, 노드/엣지 속성 포함
- **무결성 검증 리포트**: 고립 공간·문 없는 방·법규 위반 탐지 결과
- 이를 전체 데이터셋에 적용해 학습용 그래프 데이터셋(train/val/test)으로 패키징

### 측정 가능한 성공 기준
- [ ] 평면도 1장 → 위상 그래프 변환이 시각화와 함께 동작
- [ ] 손으로 라벨링한 검증셋(20장)에서 **문-방 연결 추론 정확도 ≥ 90%** (목표치, 실측 후 조정)
- [ ] 전체 평면도 변환 **성공률(파싱+그래프화) 측정값 기록**, 실패 케이스 분류
- [ ] 최종 데이터셋이 표준 스키마(아래 §5)로 직렬화되고 train/val/test 분할 완료
- [ ] 모든 단계가 `make` 또는 단일 진입 스크립트로 재현 가능

## 2. 확인된 데이터 스펙 (AI-Hub dataSetSn=71465)

> 출처: AI-Hub 공식 데이터 설명. **실제 파일로 재검증 필수.**

### 2.1 규모·구성
- 총 48,033장 (이미지 PNG) + 동수의 라벨 (JSON)
- 평면도(FP) 41,556 / 단면도(CS) 3,262 / 입면도(EP) 1,595 / 구조도(SD) 1,620
- 주택유형: 아파트(APT) / 단독주택(DEH) / 연립다세대(ROW)

### 2.2 폴더·파일명 규칙
```
239.건축 도면 데이터/
├── 원천데이터/      (PNG)
├── 라벨링데이터/    (JSON)
└── 건축 개요 및 도면정보/  (CSV 1개)

경로 계층: {주택유형}/{도면종류}/{라벨종류}/
파일명:   {주택3자}_{도면2자}_{라벨3자}_{9자리숫자}.png|json
예) APT_FP_STR_100008400.png  ↔  APT_FP_STR_100008400.json

주택종류: APT(공동주택) DEH(단독주택) ROW(연립다세대)
도면종류: FP(평면도) CS(단면도) EP(입면도) SD(구조도)
라벨종류: STR(구조) SPA(공간) OBJ(객체) OCR(문자)
```
> ※ 한 도면 이미지가 STR/SPA/OBJ/OCR 라벨로 나뉘어 별도 파일로 존재함에 주의.
> 동일 도면의 여러 라벨을 `{9자리숫자}` 키로 묶어야 한다.

### 2.3 라벨(JSON) 구조 — COCO 형식
```jsonc
{
  "categories": [{ "id": int, "name": str }, ...],   // 클래스 정의
  "images":     [{ "id", "width", "height", "file_name" }],  // 배열 길이 1 고정
  "annotations":[{
     "id", "image_id", "category_id",
     "segmentation": [[x1,y1,...,xn,yn]],  // 폴리곤(픽셀 좌표)
     "area": number,                        // bbox 면적
     "bbox": [x1,y1,width,height],          // 좌상단 기준
     "iscrowd": 0|1,
     "attributes": { ... }                  // 라벨종류별 상이 — 실데이터로 확인
  }]
}
```

### 2.4 클래스 (소분류)
- **구조 STR (8)**: 출입문(여닫이문/미닫이문/기타문), 창호(여닫이창/미닫이창/기타창), 벽체(철근콘크리트벽/기타벽)
- **공간 SPA (12)**: 거실, 침실, 주방, 현관, 발코니, 화장실, 실외기룸, 드레스룸, 기타(다목적), 엘리베이터홀, 계단실, 엘리베이터
- **객체 OBJ (5)**: 변기, 세면대, 싱크대, 욕조, 가스레인지
- **문자 OCR**: 텍스트

### 2.5 건축 개요 CSV
도면별 메타: `FileName, site_area, building_area, building_vtl_rate(용적률), building_coverage(건폐율), design_stage, file_extension, width, height, large_id, middle_id, drawing_id, area, scale(축척)`
> **중요**: 픽셀↔실측(㎡, m) 변환에 `scale`/`area`/`width`/`height`가 필요. 법규 면적 검증의 전제.

## 3. Phase 1 — 추출 및 구조화 (Task 1-1 ~ 1-5)

### Task 1-1. 압축 해제 & 인벤토리
- **입력**: `data/raw/` 하위의 중첩 zip / 분할압축(`.zip.part*`)
- **처리**: 분할압축 병합 → 재귀적 zip 해제 → 파일 인벤토리(PNG/JSON 개수, 도면종류별 분포)
- **출력**: `data/interim/inventory.csv` (파일경로, 주택유형, 도면종류, 라벨종류, 도면키)
- **완료 기준**: 평면도 PNG/JSON 쌍 개수가 명세(41,556 부근)와 대조되고, 짝 안 맞는 고아 파일 목록이 리포트됨

### Task 1-2. 라벨 파싱 → 기하 객체화
- **입력**: 한 도면키의 STR/SPA/OBJ JSON + 개요 CSV 행
- **처리**:
  - COCO JSON 파싱, `category_id → 클래스명` 매핑 테이블 구축(실데이터에서 추출)
  - 각 `segmentation` 폴리곤 → `shapely.Polygon`
  - 깨진 폴리곤(self-intersection 등)은 `buffer(0)`로 보정, 보정 실패는 격리
  - `scale`로 픽셀→실측(㎡) 변환 함수 작성
- **출력**: 도면별 중간 표현 `{rooms[], doors[], windows[], walls[], objects[]}` (각 요소에 폴리곤·면적·클래스)
- **완료 기준**: 1장에 대해 방/문/창/벽 개수와 면적이 도면 위에 오버레이 시각화로 확인됨

### Task 1-3. ★Topology Extraction (방-문-방 그래프) — 최대 난관
- **입력**: Task 1-2의 기하 객체
- **처리**:
  - **노드** = 공간(SPA) 폴리곤
  - **엣지 추론(핵심)**: 각 출입문(STR-출입문) 폴리곤에 대해, 그 문에 **인접한 두 공간**을 기하로 찾는다.
    - 권장 접근: 문 폴리곤을 약간 buffer → 교차/근접하는 SPA 폴리곤 후보 추출 → 가장 가까운 2개를 연결. 문이 벽 개구부에 놓인 점을 이용(문 중심에서 법선 방향 양쪽 공간).
    - 1:1로 안 떨어지는 경우(현관-복도-거실 개방형, 문 1개에 공간 3개 접함 등)의 처리 규칙을 정의하고 `NOTES.md`에 기록.
  - **현관 식별**: SPA-현관 노드를 외부 진입점으로 표시. 외부 연결 엣지 추가.
  - **창호**: 채광 검증용으로 각 방의 창 개수/길이를 노드 속성에 저장(엣지는 아님).
  - `networkx.Graph` 생성. 노드 속성(클래스, 면적, 중심좌표, 창 보유), 엣지 속성(문 종류).
- **출력**: 도면별 `graph.json`(node-link 형식) + 그래프 시각화 PNG
- **완료 기준**: 손으로 검증한 20장에서 문-방 연결 정확도 측정·기록. **목표 ≥90%**, 미달 시 알고리즘 보완 반복.
- **주의**: 이 Task는 1회에 완성되지 않는다. baseline → 오류 분석 → 규칙 보강 사이클을 명시적으로 돌려라.

### Task 1-4. 공간 온톨로지 (OWL)
- **처리**: `owlready2`로 §2.4 실제 클래스에 1:1 매핑되는 온톨로지 설계
  - 위계: Public(거실/현관) / Private(침실/드레스룸/화장실) / Service(주방/발코니/실외기룸/계단실 등)
  - 관계: `connectedTo`, `adjacentTo`, 프라이버시 속성
- **출력**: `ontology/floorplan.owl` + 클래스 다이어그램
- **완료 기준**: Task 1-3 그래프를 온톨로지 인스턴스로 적재 가능

### Task 1-5. 법규/무결성 규칙 엔진
- **처리**: 강행규정 우선, 모듈형. 우선 구현할 규칙(예시 — 실제 수치는 `DECISIONS_NEEDED.md`로 확인):
  - 무결성: 고립 공간 없음(그래프 연결성), 문 없는 방 없음(degree≥1), 현관에서 전 공간 도달 가능
  - 법규: 침실 최소면적, 거실·침실 채광(창 인접), 피난 동선
- **구현**: 1차는 networkx 기반 순수 파이썬 규칙 함수. (SWRL/추론기는 온톨로지 안정화 후 선택 도입)
- **출력**: 도면별 `validation_report.json` (위반 항목·근거)
- **완료 기준**: 의도적으로 흠집 낸 그래프(문 제거 등)에서 위반을 정확히 탐지

## 4. Phase 2 — 데이터셋 구축 (Task 2-1 ~ 2-4)

### Task 2-1. 전체 일괄 변환 + 품질 필터
- **처리**: Phase 1 파이프라인을 평면도 전체에 병렬 적용. 변환 실패(폴리곤 깨짐, 문-방 추론 실패, 그래프 비정상)를 사유별 분류·격리.
- **출력**: `data/processed/graphs/*.json`, `data/processed/quality_report.csv`(성공/실패 사유·비율)
- **완료 기준**: 전체 성공률과 실패 사유 분포가 리포트됨. 임계 이하 품질은 데이터셋에서 제외.

### Task 2-2. 표준 그래프 스키마로 정규화
- **처리**: §5 스키마로 통일 직렬화. 노드/엣지/그래프 레벨 속성 고정. 좌표 정규화(0~1) 버전과 실측 버전 병기.
- **출력**: `data/processed/dataset/*.json`

### Task 2-3. 글로벌 데이터 어댑터 (사전학습용)
- **목표**: 형식이 다른 외부 데이터셋을 **동일한 §5 스키마**로 변환하는 어댑터.
  - RPLAN: 래스터 형식 → 그래프 추출 어댑터 (※ 접근/라이선스 확인 필요)
  - CubiCasa5k: 이미지+SVG 벡터 주석 → 그래프 어댑터
- **출력**: `src/adapters/rplan.py`, `src/adapters/cubicasa.py` + 변환 결과
- **주의**: AI-Hub(COCO)·RPLAN(raster)·CubiCasa(SVG)는 형식이 전부 다르다. **공통 스키마로의 통일이 이 Task의 본질.** 통일이 안 되면 사전학습→파인튜닝이 따로 논다.

### Task 2-4. 분할·버전·문서화
- **처리**: train/val/test 분할(누수 방지: 같은 단지/평형 중복 주의), 데이터시트 작성, 코드·데이터 버전 태깅
- **출력**: `dataset_card.md`(통계·클래스 분포·알려진 한계), `splits/`

## 8. 작업 순서 (체크포인트)
1. Task 1-1 → 인벤토리 확인 (사람 리뷰)
2. Task 1-2 + 1-3을 **1장**으로 완성 → 시각화 리뷰 (사람 리뷰)  ← 가장 중요한 게이트
3. 손검증셋 20장으로 1-3 정확도 측정 → 목표 미달 시 보강
